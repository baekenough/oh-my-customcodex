# R010: Orchestrator Coordination Rules

The main conversation is the sole orchestrator and MUST NEVER directly write, edit, or create files — all file modifications MUST be delegated to appropriate subagents.

## Overview

The orchestrator's role is routing and coordination only. File operations, git commands, and all write actions must go through specialist subagents. This ensures separation of concerns, maintains audit trails, and prevents accidental bulk changes from the orchestrator context.

## Priority

**MUST** — Critical. Direct file writes from the orchestrator are violations. Advisory PostToolUse hook monitors compliance. Candidate for hard-block promotion per [[r021]].

## Key Requirements

**Delegation table (key entries):**

| Task Type | Required Agent |
|-----------|---------------|
| Create agent/skill/guide | `mgr-creator` |
| Git operations | `mgr-gitnerd` |
| Memory operations | `sys-memory-keeper` |
| Python/FastAPI | `lang-python-expert` / `be-fastapi-expert` |
| Go code | `lang-golang-expert` |
| TypeScript/Next.js | `lang-typescript-expert` / `fe-vercel-agent` |
| Docker/Infra | `infra-docker-expert` |
| Database schema | `db-supabase-expert` |
| Unmatched specialized task | `mgr-creator` → dynamic agent creation |

**Protected paths (mgr-creator required):**
- `.codex/agents/*.md`
- `.codex/skills/*/SKILL.md`
- `guides/*/` (new directories)

**Orchestrator allowed operations:** Read, Glob, Grep only (read-only).

**Dynamic agent creation:** When no matching agent exists → delegate to `mgr-creator` with domain keywords, file patterns, and required capabilities. mgr-creator auto-discovers relevant skills/guides and creates the agent.

**Agent Teams exception:** Agent Teams members are peers and CAN spawn sub-agents to execute complex workflows.

**Sub-agent nesting (v2.1.172+, platform capability):** Claude Code now allows sub-agents to spawn their own sub-agents up to 5 levels deep. oh-my-customcodex retains the sole-orchestrator design as a deliberate project architecture choice for predictable R009 parallelism and R018 coordination — not because of a platform limitation. The only sanctioned nesting path is the Agent Teams exception above.

## Agent Capability Pre-Check

Delegation must account for frontmatter capabilities before the agent is spawned.

| Prompt requires | Target agent must have |
|-----------------|------------------------|
| Shell, CLI, package manager, test, build, GitHub CLI, or script execution | `tools` includes `Bash` |
| `gh`, `git`, `npm`, `bun`, `pnpm`, `yarn`, `python`, `node`, `curl`, `jq`, `make`, or `docker` work | `tools` includes `Bash` and `disallowedTools` does not include `Bash` |
| Documentation-only synthesis from supplied evidence | No Bash requirement |

`arch-documenter` explicitly disallows Bash, so it must not be asked to inspect GitHub issues or run commands. Collect evidence first with a Bash-capable lane, then delegate the writing.

## Delegated Permission Ownership

R010 is the canonical owner of provider-specific delegated permission guidance.

| Provider surface | Requirement |
|------------------|-------------|
| Codex/OMX native | `spawn_agent` has no `mode` parameter. Select an installed OMX `agent_type`; filesystem and approval behavior come from the compiled role and active runtime policy. Do not pass Claude-only `mode` or `bypassPermissions` fields. |
| Claude compatibility | Pass `mode: "bypassPermissions"` to the compatibility `Agent` call only when the active Claude session uses bypass permissions; otherwise do not claim that mode. |

In both cases, the delegation prompt still states write scope, allowed actions, forbidden actions, and authorization boundaries. Inline reminders may remain in compatibility skills because measured delegation failures showed that a distant rule reference can be lost.

## Historical Sensitive-Path Bypass

The universal `/tmp` artifact-wrapper guidance for Claude compatibility paths is deprecated for current Claude Code runtimes:

- Claude Code v2.1.121+ with `bypassPermissions` permits direct writes to `.claude/skills/`, `.claude/agents/`, and `.claude/commands/`.
- Claude Code v2.1.126+ extends that behavior to broader protected paths such as `.claude/**`, `.git/**`, and `.vscode/**`.
- Codex-native `.codex/**` edits use the normal Codex edit/patch flow.
- Keep `/tmp/{skill}-{timestamp}.md` only as a legacy fallback for older Claude Code versions or sessions that still prompt.

**Background-agent project-settings isolation (v2.1.172+):** Fixed background agents potentially reading another directory's project settings (`.mcp.json` approvals, trust) when dispatched onto a pre-warmed worker. A `/bg`-dispatched agent now correctly reads its own project settings.

## Pre-Delegation Privileged-Scope Boundary (proactive)

> Origin: upstream #1368 #5 — an infra subagent was delegated a prod-touching task with no explicit approval boundary in the delegation prompt; it freely ran prod DB queries, file deletes, and SMS reads, tripping the safety classifier 3+ times.

The Subagent Scope-Creep STOP Protocol is reactive: it halts an agent after classifier trips. This is its proactive complement: prevent trips by stating the boundary before the subagent runs.

When delegating ANY task that touches prod or privileged resources (prod DB, infra deletion, credential stores, external messaging/SMS, shared-namespace secrets), the orchestrator MUST state explicitly in the delegation prompt the approved actions, forbidden actions, and authorization scope.

| Anti-pattern | Required |
|--------------|----------|
| Delegate a prod/privileged-touching task with no scope or forbidden-line in the prompt | State approved action(s), explicit forbidden actions (for example: do NOT delete files, do NOT query prod DB, do NOT read SMS/messages), and authorization scope |

Cross-reference: [[r001]] credential/privileged-scope guardrails and the Subagent Scope-Creep STOP Protocol.

Advisory/guard hooks (`git-delegation-guard.sh`, `agent-capability-precheck.sh`) + PostCompact re-injection per [[r021]]. Candidate for additional hard-blocking if direct-write violations exceed 3/session.

## Claude background isolation update

R010 now records Claude Code v2.1.174 background-session isolation fixes: `/bg` sessions no longer inherit foreign `ANTHROPIC_*` provider env values and pre-warmed workers recover authentication correctly. This reduces Claude-template false blockers; Codex/OMX keeps explicit routing and permission boundaries.


## Claude Background Reliability and New-File Count Pre-Check

R010 now records Claude Code v2.1.198-v2.1.200 background-agent reliability improvements as compatibility notes only: auto-commit/push/draft-PR behavior, partial-work returns, and sleep/wake/stale-lock/daemon/roster/socket-token hardening still require explicit Git/GitHub verification in Codex workflows.

Before delegating a new-file addition, measure whether it creates a new top-level topic/entity directory or only adds a file under an existing directory. Use measured counts (for example with `find <dir> -mindepth 1 -maxdepth 1 -type d | wc -l`) and tell delegates to sync based on evidence, not guesses.
