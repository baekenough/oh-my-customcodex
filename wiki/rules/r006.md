# R006: Agent Design Rules

Defines the file format, required frontmatter, optional fields, naming conventions, and separation-of-concerns architecture for all agents and skills.

## Overview

Agents live in `.codex/agents/{name}.md`. Skills live in `.codex/skills/{name}/SKILL.md`. Guides in `guides/`. These three locations have distinct purposes and must not be conflated. The agent frontmatter defines identity, tools, a provider-neutral model lane, native reasoning effort, and behavior. The body describes role and workflow — not detailed instructions (those belong in skills).

## Priority

**MUST** — Agent files with invalid frontmatter or wrong structure cause routing failures and R017 verification failures.

## Key Requirements

**Required frontmatter fields:** `name`, `description`, `model_lane`, `model_reasoning_effort`, `tools`

**Codex/OMX model lanes:**

| Lane | Resolution | Use Case |
|------|------------|----------|
| `inherit` | Active Codex session | Session-owned routing |
| `frontier` | Current Codex/OMX frontier contract | Implementation and deep reasoning |
| `spark` | Installed OMX Spark contract | Search and lightweight validation |

Concrete model IDs come from the installed Codex/OMX contract. Claude aliases remain only in packaged compatibility sources and are normalized by the compiler.

## Memory Provider Boundary

`memory` is compatibility/source metadata, not native Codex compiler output. The compiler does not emit it into native Codex TOML or compiled config, so frontmatter alone cannot enable native persistence; native Codex uses active runtime memory.

| Scope | Compatible consumer location | Git tracked |
|-------|------------------------------|-------------|
| `user` | `~/.codex/agent-memory/<name>/` | No |
| `project` | `.codex/agent-memory/<name>/` | Yes |
| `local` | `.codex/agent-memory-local/<name>/` | No |

Managed packaged agents default to `local`; custom agents may explicitly opt into `project`. Compatible consumers load the first 200 MEMORY.md lines when they support this metadata.

**Separation of concerns:**

| Location | Purpose | Contains |
|----------|---------|----------|
| `.codex/agents/` | WHAT the agent does | Role, capabilities, workflow |
| `.codex/skills/` | HOW to do tasks | Instructions, scripts, rules |
| `guides/` | Reference docs | Best practices, tutorials |

**Skill scope:**

| Scope | Deployed via init? |
|-------|--------------------|
| `core` | Yes |
| `harness` | Yes |
| `package` | No |

**Protected paths:** `.codex/agents/*.md`, `.codex/skills/*/SKILL.md`, `guides/*/` (new dirs) — creation MUST go through `mgr-creator` per [[r010]].

## Artifact Output Convention

Skills persist output to `.codex/outputs/sessions/{YYYY-MM-DD}/{skill-name}-{HHmmss}.md`. Opt-in, git-untracked. Final subagent writes per [[r010]] using file-write APIs that create missing parent directories.

## Sensitive Path Handling

Claude Code still treats `.claude/` and `templates/.claude/` as protected compatibility surfaces, but the current behavior is version-sensitive rather than a universal prompt wall.

This Codex port uses `.codex/` as the active runtime surface. `.codex/**` edits should use the normal Codex edit/patch flow with no Claude-only `/tmp` wrapper.

Current compatibility rule:

- **CC v2.1.121+**: `bypassPermissions` no longer prompts for direct writes to `.claude/skills/`, `.claude/agents/`, and `.claude/commands/`.
- **CC v2.1.126+**: `bypassPermissions` also bypasses prompts for broader protected paths such as `.claude/**`, `.git/**`, `.vscode/**`, and shell config files.
- **Historical fallback only**: if the target runtime is older than v2.1.121, not running with `bypassPermissions`, or still surfaces a protected-path prompt, use `/tmp/{skill}-{timestamp}.md` only as a compatibility fallback for the final `.claude/**` or `templates/.claude/**` write.

| Path pattern | Guidance |
|--------------|----------|
| `.claude/skills/**`, `.claude/agents/**`, `.claude/commands/**` | Direct writes are acceptable in Claude Code `bypassPermissions` on v2.1.121+ |
| `.claude/**`, `.git/**`, `.vscode/**`, shell config files | Direct writes are acceptable in Claude Code `bypassPermissions` on v2.1.126+ |
| `templates/.claude/**` | Mirror deliberately; use the historical `/tmp` fallback only when the runtime still prompts |
| `.codex/**` | Normal Codex runtime writes; still follow [[r010]]/[[r017]] |
| `.codex/outputs/**` and `.claude/outputs/**` | Treat as constrained artifact paths; use file-write APIs that create parents and do not pre-create with Bash |

Recommended practice:

1. Prefer direct Write/Edit for `.codex/**` and for compatible `.claude/**` targets when the runtime version and permission mode allow it.
2. Keep allow rules only as defensive documentation; current behavior depends on Claude Code version and permission mode, not allow-rule wishful thinking.
3. In this Codex port, update `.codex/...` source files and their `templates/.claude/...` mirrors deliberately instead of bulk-copying with shell commands.
4. Use the historical `/tmp` artifact-body fallback only for legacy Claude Code versions or sessions that still prompt on protected paths.
5. When compatibility-template writes still require a fallback, verify the resulting diff and remove stale wrapper boilerplate from repeated prompts.

Delegation prompt requirement:

Any delegated prompt that touches `.claude/**`, `templates/.claude/**`, `.claude/outputs/**`, or read-only measurement of those paths must include `Sensitive-path compatibility note` from `.codex/rules/MUST-agent-design.md`.

Delegated permission ownership belongs to [[r010]]. Native Codex/OMX `spawn_agent` has no `mode` parameter, so native calls must not invent `mode` or `bypassPermissions`. Before Claude Code v2.1.212, a compatibility `Agent` call passes `mode: "bypassPermissions"` only when the active Claude session itself uses bypass permissions; v2.1.212+ ignores the field and inherits the parent session mode.

Long optional frontmatter examples and compatibility tables are retained in HTML `DETAIL` blocks in the source rule and can be loaded with a direct Read when needed.


## Claude Compatibility Model Restrictions

**`availableModels` subagent overrides (v2.1.172+):** `availableModels` restrictions now apply to subagent `model:` overrides, the agent dispatch model picker, and the advisor model. Allowlists using version-specific IDs should account for Opus/Sonnet 1M picker rows and avoid doubled 1M suffix handling. Relevant when restricting per-agent model overrides in packaged Claude compatibility templates.

**Fable 5 `[1m]` auto-normalization (v2.1.173+):** Fable 5 model IDs carrying a `[1m]` suffix are auto-normalized because Fable 5 includes 1M context by default. Use `claude-fable-5` / `model: fable` without `[1m]`; the suffix remains meaningful for Opus/Sonnet IDs. Codex-native agents continue to follow the OMX model contract.

## Claude v2.1.204-v2.1.208 agent compatibility

Claude Code v2.1.204 fixes headless `SessionStart` hook streaming so an active remote worker is not reaped as idle. Claude Code v2.1.208 makes an Agent `tools:` list that resolves empty fail clearly and names its unrecognized entries. These are provider-owned validation and lifecycle fixes; Codex-native agents still use installed OMX roles, valid tool surfaces, and explicit `agent_type` dispatch.

## Claude v2.1.210 positional placeholder compatibility

Claude Code preserves unmatched `$1` and `$2` positional placeholders verbatim instead of silently stripping them. Claude compatibility skills must handle absent arguments explicitly with default text, an `$ARGUMENTS` guard, or `argument-hint`. This provider-owned expansion rule does not change Codex/OMX skill parsing, agent frontmatter, or native dispatch.

## Claude v2.1.212-v2.1.214 agent compatibility

Claude Code v2.1.212 deprecates the Agent/Task `mode` field and inherits permission state from the parent session. v2.1.214 makes a hook `if:` pattern `dir/**` current-directory-only; use `**/dir/**` for any-depth matching. These provider-owned rules do not add native Codex dispatch arguments.

It also records Claude Code v2.1.198-v2.1.201 compatibility notes for Explore model inheritance, extended-thinking inheritance, hook stderr visibility, stacked slash-skill loading depth, `default` permission mode being relabeled as `Manual`, and Sonnet 5 harness-reminder delivery no longer using mid-conversation `system` role messages. Codex-native agents still follow OMX role/model routing.

## Claude Compatibility: Safe Mode and Bundled Skill Control (v2.1.169)

Claude compatibility templates should know that `--safe-mode` / `CLAUDE_CODE_SAFE_MODE` disables customizations for regression isolation, while `disableBundledSkills` / `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS` hides bundled skills, workflows, and built-in slash commands from the model. These are Claude platform settings, not Codex/OMX routing controls, and are distinct from advisory `skills:` frontmatter metadata.
