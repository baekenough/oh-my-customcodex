# R011 Memory Integration

Defines native Codex memory ownership, compatibility frontmatter scopes, and optional searchable MCP integration.

## Overview

Use active Codex memory first. Agent frontmatter `memory: user|project|local` is compatibility metadata; the compiler does not emit it into native Codex TOML or compiled config, so the field cannot enable native persistence by itself. An AgentMemory-compatible MCP may supplement native memory only for cross-session search. Memory failures must never block the main task.

## Key Rules

- Consult memory before starting long-running work.
- Save durable learnings after significant decisions or discoveries.
- Use the active Codex runtime's memory surfaces first.
- Treat frontmatter `memory` as compatibility metadata, not proof of native persistence.
- Keep packaged agents on `local`; reserve `project` for explicit custom-agent opt-in.
- Use approved searchable MCP tools only when configured.
- Do not store secrets or duplicate AGENTS.md content.

## Compatibility Scope Metadata

Compatible consumers create the selected directory, grant memory-path tools, and load the first 200 MEMORY.md lines. Claude compatibility settings may override the location with `autoMemoryDirectory`.

| Scope | Location | Git tracked |
|-------|----------|-------------|
| `user` | `~/.codex/agent-memory/<name>/` | No |
| `project` | `.codex/agent-memory/<name>/` | Yes |
| `local` | `.codex/agent-memory-local/<name>/` | No |

## Responsibility Split

| Task | Owner |
| --- | --- |
| MEMORY.md updates | sys-memory-keeper |
| Searchable MCP save | Orchestrator |
| Session-end check | Orchestrator |

## Compatibility `memory: project` Source-Tree Pollution Guard

Compatible consumers working from source subdirectories must not create nested `.codex/agent-memory/` or `.claude/agent-memory/` directories inside source packages. An explicitly opted-in `project` scope resolves to the repository-root surface. Before commit, remove nested memory pollution.

## Historical Provenance

Issue #869 remains the provenance for the v0.87.2-v0.88.0 memory and verification lessons. The original feedback records were later consolidated or removed, so their former filenames are historical identifiers rather than live file references.

## Claude v2.1.210 read-limit compatibility

Claude Code returns an explicit error when a memory write would push `MEMORY.md` past its read limit rather than silently truncating the loaded index. Treat the write as non-blocking but not successful: archive or trim Cold entries and retry. This provider-owned guard does not change native Codex/OMX memory ownership or its configured budget.
