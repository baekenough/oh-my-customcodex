# R007: Agent Identification Rules

Every response MUST begin with an agent identification header so users always know which agent is active and why.

## Overview

Identification provides traceability and transparency. Without it, users cannot distinguish which agent generated a response or which skill is active. The header also reflects the active routing context (secretary-routing, dev-lead-routing, etc.) when applicable.

## Priority

**MUST** — Enforced. Omission of identification header requires immediate correction. PostCompact hook re-injects this rule after context compaction.

## Key Requirements

**Full header format:**
```
┌─ Agent: {agent-name} ({agent-type})
├─ Skill: {skill-name} (if applicable)
└─ Status: {current-action-or-verdict}
```

Intermediate metadata lines use `├─`. Only the final metadata line uses `└─`.

**Short response discipline:** Brief answers, diagnostics, status pings, and corrections are not exempt. User-visible responses still start with the full header even if the body is one sentence. Legacy bracket shorthand is only for internal logs or non-user-facing scratch output.

**Routing context identification:**

| Context | Identification |
|---------|---------------|
| No routing active | `Codex (default)` |
| secretary-routing | `Codex (secretary-routing)` |
| dev-lead-routing | `Codex (dev-lead-routing)` |
| Skill invocation | `Codex → {skill-name}` |

**Skill invocation — integrated format (NOT separate display):**
```
┌─ Agent: Codex → {skill-name}
└─ Status: {current-action-or-verdict}
```

Verbose skill-invocation violation examples remain available in the source rule's `DETAIL` block. Moving those examples out of the default context changes loading cost, not the identification obligation or header format.

## Enforcement

Advisory PostToolUse hook + PostCompact re-injection per [[r021]]. Candidate for hard-block promotion if omission rate exceeds 20%.
