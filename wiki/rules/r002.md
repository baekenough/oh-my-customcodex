# R002: Permission Rules

Defines tool permission tiers and file access boundaries for all agents.

## Overview

Tools are grouped into six tiers from always-allowed read-only tools to conditionally-available MCP tools. File access is scoped to the project. Agents must not attempt operations beyond their tier without explicit approval.

## Priority

**MUST** — Permission violations can cause unintended state changes or security breaches across the system.

## Key Requirements

**Tool tiers:**

| Tier | Tools | Policy |
|------|-------|--------|
| 1: Always | Read, Glob, Grep, ToolSearch | Free use, read-only |
| 2: Default | Write, Edit, NotebookEdit | State changes; notify before modifying important files |
| 3: Context | Agent, Skill, EnterPlanMode, ExitPlanMode, Monitor, TodoWrite, AskUserQuestion | Context-dependent, no user approval |
| 4: Approval | Bash, WebFetch, WebSearch | Request user approval on first use |
| 5: Conditional | Agent Teams tools (TeamCreate, SendMessage, etc.) | Available when Agent Teams enabled |
| 6: MCP | ListMcpResourcesTool, ReadMcpResourceTool, CronCreate, etc. | Available when MCP servers configured |

**File access:**

| Operation | Allowed | Prohibited |
|-----------|---------|-----------|
| Read | All source, configs, docs | — |
| Write | Source code, new files in project | `.env`, `.git/config`, paths outside project |
| Delete | Temp files created by agent | Existing files without request, entire directories |

**Permission request format:**
```
[Permission Request]
Action: {action} | Required: {tool} | Reason: {why} | Risk: Low/Medium/High
Approve?
```

## Claude Code Compatibility

Codex-native `.codex/**` edits are normal project writes and do not require the historical Claude-only `/tmp` bypass pattern.

Claude Code compatibility behavior is version-sensitive:

- CC v2.1.121+ with `bypassPermissions` no longer prompts for writes to `.claude/skills/`, `.claude/agents/`, and `.claude/commands/`.
- CC v2.1.126+ with `bypassPermissions` also covers broader protected paths such as `.claude/**`, `.git/**`, `.vscode/**`, and shell config files.
- Use `/tmp/{skill}-{timestamp}.md` only as a legacy fallback for older Claude Code versions, non-bypass sessions, or runs that still surface protected-path prompts.

**CC v2.1.200+ Manual label + AskUserQuestion behavior:** Claude Code now displays `default` permission mode as `Manual` and accepts `--permission-mode manual` / `"defaultMode": "manual"` alongside `default` with identical behavior. `AskUserQuestion` no longer auto-continues by default, so autonomous flows such as FSD should avoid question tools unless blocked and proceed on best judgment for low-risk reversible work. Non-array `.claude.json` MCP server lists no longer crash Claude startup.

**CC v2.1.203-v2.1.208 permission updates:** v2.1.203 adds a grey pause badge to the footer while Manual mode is active. v2.1.207 removes the provider opt-in for supported Auto mode deployments, adds managed `disableAutoMode`, and fixes noninteractive remote managed-settings consent. v2.1.208 compiles and caches each permission matcher once. These are Claude provider behaviors; the Codex/OMX sandbox and approval policy remain unchanged.

**CC v2.1.210 permission matcher validation:** Claude warns when settings use unsupported path-scoped `Write(path)`, `NotebookEdit(path)`, or `Glob(path)` permission matchers. Use `Edit(path)` for file-write scopes and `Read(path)` for read/glob scopes. This provider-owned matcher grammar does not change the Codex/OMX tool tiers, sandbox, or approval policy.

## Claude v2.1.212-v2.1.214 permission compatibility

Claude Code v2.1.212 ignores the delegated Agent/Task `mode` field and inherits the parent session permission mode. v2.1.214 narrows a single-segment `dir/**` allow matcher to the current working directory; use `**/dir/**` for any-depth matching, while `deny` and `ask` stay any-depth. These are provider-owned changes and do not alter Codex/OMX policy.

## Enforcement

Prompt-based per [[r021]]. On insufficient permission: do not attempt, notify user, suggest alternative.
