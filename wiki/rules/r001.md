# R001: Safety Rules

Defines absolutely prohibited actions and required verification steps before any destructive operation.

## Overview

Prevents agents from performing irreversible or dangerous actions such as exposing secrets, deleting system files, or making unauthorized network requests. Any potential violation triggers an immediate full stop and user notification.

## Priority

**MUST** — Non-negotiable. Safety violations can cause irreversible data loss or security breaches.

## Key Requirements

**Prohibited actions:**

| Category | Prohibited |
|----------|-----------|
| Data | Expose API keys/secrets/passwords, collect PII, log auth tokens |
| File System | Modify `/etc`, `/usr`, `/bin`; delete outside project; modify `.env`/`.git/config` without approval |
| Commands | `rm -rf /` or broad deletes, shutdown/restart, sudo/su, network config changes |
| External | Access URLs without approval, send user data externally, download/execute unknown scripts |

**Before any destructive operation:**
1. Verify target
2. Assess impact scope
3. Check recoverability
4. Get user approval

**On violation:**
1. Stop all operations
2. Preserve current state
3. Report: what detected, why risky, action taken
4. Wait for instructions

## Enforcement

Prompt-based (AGENTS.md + .codex/rules/) per [[r021]]. Some specific patterns enforced by `stage-blocker` hard-block hook.

## Relationships

- **Related rules**: [[r002]], [[r004]], [[r010]]
- **Affects**: All agents with Bash or WebFetch access

## Infra-Diagnostic Metadata and Standing-Deny Guards

- **Infra-diagnostic metadata only**: during health or infrastructure diagnosis, check secret-bearing files with metadata commands such as `ls -la`; do not read `.env`, OAuth, kube, or credential JSON contents into the transcript just to prove existence.
- **Standing user-deny + classifier block**: when the user has a standing "do not touch X" constraint and a safety classifier blocks an action on X once, stop retrying and switch to a user-runs command/instruction path.
- **Infra deletion blast radius**: before tunnel, DNS, k8s, load-balancer, or security-group deletion, enumerate every served endpoint/route/selector/rule and prefer reversible disable/detach actions.
