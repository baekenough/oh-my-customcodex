## Provider Boundary and Non-Scope

Package-owned work is limited to compatibility guidance, mirrors, wiki summaries,
tests that lock those contracts, and release metadata. The following remain
Claude-owned external behavior and must not be implemented locally:

- `/config` dynamic workflow sizing, Claude OTel emission, footer badges, and UI;
- auto mode, managed-settings consent, permission matcher caching/classification;
- SessionStart event transport, transcript protection, worktree deletion;
- `/doctor`, `/commit-push-pr`, `remote.pushDefault` auto-allow behavior;
- `CLAUDE_CODE_PROCESS_WRAPPER`, background daemon/session lifecycle, dialogs;
- Agent/Edit/Read/Grep/Glob implementations or Claude tool-error handling.

Explicit exclusions:

- no `src/**`, dependency, `bun.lock`, hook wiring, or runtime configuration edit;
- keep `package.json` and `templates/manifest.json` `requiresCC` plus
  `claudeCode.minimumVersion` at `>=2.1.121` / `2.1.121`;
- keep `MINIMUM_OMX_VERSION` at `0.20.2` and add no Codex minimum version;
- do not port the parent `memory: project -> local` migration, agent changes, or
  `.gitignore` changes; those belong to separate issue #1656;
- do not port the parent's `guides/claude-code-tracking.md` version-number edit;
- do not copy v1.1.18's incidental historical-note HTML archival/refactor;
- add no guide/rule/wiki inventory entry because every target file already exists.

## Canonical Standalone Lock

The linked worktree can emit `root: "codex-project"`; it is not canonical.
After all content and generated plugin assets settle, copy tracked and intended
untracked files into a fresh standalone directory and generate there:

```bash
canonical_root="$(mktemp -d)"
export canonical_root
bash -lc '
  set -euo pipefail
  git ls-files -co --exclude-standard -z |
  while IFS= read -r -d "" file_path; do
    mkdir -p "$canonical_root/$(dirname "$file_path")"
    if [[ -L "$file_path" ]]; then
      cp -a "$file_path" "$canonical_root/$file_path"
    else
      cp -p "$file_path" "$canonical_root/$file_path"
    fi
  done
  cd "$canonical_root"
  bun run scripts/sync-source-lockfile.ts
'
cp "$canonical_root/.omcodex.lock.json" .omcodex.lock.json
rm -rf "$canonical_root"
node - <<'NODE'
const lock = require('./.omcodex.lock.json');
if (lock.generatorVersion !== '1.0.23' || lock.templateVersion !== '1.0.23') process.exit(1);
if (Object.keys(lock.files).length !== 243) process.exit(1);
if (Object.values(lock.files).some((entry) => Object.prototype.hasOwnProperty.call(entry, 'root'))) process.exit(1);
NODE
node scripts/verify-package-contract.mjs --skip-build
```

## Release Flow

1. Confirm no `v1.0.23` tag or conflicting branch exists; rename the current
   local head exactly `release/v1.0.23`.
2. Commit the reviewed allowlisted diff using the Lore commit protocol, push the
   release branch, and open a PR to `develop` with seven separate lines:
   `Closes #1650` through `Closes #1655`, plus `Closes #1660`.
3. Require CI, Docs Sync, Wiki Sync, package, security, and review gates green.
4. Merge the PR. Do **not** create or push a tag manually.
5. Observe `.github/workflows/auto-tag.yml` waiting for required `develop`
   workflows, creating annotated `v1.0.23` at the merge SHA, closing linked
   issues/milestone #28 provisionally, and deleting `release/v1.0.23`.
6. Observe tag-triggered `.github/workflows/release.yml` through successful npm,
   GitHub Packages, and GitHub Release publication.

## Failure Recovery and Fix-Forward

- Before merge/tag: fix on `release/v1.0.23`; do not weaken tests or gates.
- After merge but before publication: let required workflow failure prevent the
  tag, preserve evidence, and repair through a normal reviewed commit/PR.
- If auto-tag provisionally closes issues/milestone but release publication
  fails, reopen them before the next attempt.
- Once either registry publishes `1.0.23`, never delete/reuse the version or tag;
  preserve the immutable release and fix forward as `v1.0.24`.
- Do not use `git reset --hard`, force push, manual tag deletion/recreation, or
  destructive rollback. Tag/GitHub Release deletion requires authoritative proof
  that neither registry published and explicit maintainer approval.
