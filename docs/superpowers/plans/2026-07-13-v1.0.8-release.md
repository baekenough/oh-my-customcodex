# v1.0.8 Auto-Dev Release Plan — 2026-07-13

## Scope

Process the nine current auto-dev-eligible harness reliability, performance, and security issues:

| Issue | Area | Disposition |
|-------|------|-------------|
| #1578 | CLI preflight | Remove the fixed post-check delay, make subprocess timeouts cancellable, and use Codex/OMX as the default provider checks. |
| #1579 | Update preservation | Preserve protected rules and nested customized files across repeated updates with consistent destination-relative paths. |
| #1580 | Dry-run safety | Keep update previews read-only by blocking config, lockfile, installer, registry, self-update, and network side effects. |
| #1581 | Failure reporting | Distinguish skipped work from execution failures and propagate init, component, and batch failures through API results and CLI exit status. |
| #1582 | Eval collection | Read Codex task outcomes first, retain an explicit Claude compatibility fallback, and expose missing, malformed, and duplicate-record diagnostics. |
| #1585 | Updater path boundary | Reject absolute, traversal, and symlink-escape paths before public updater helpers can read or write outside the target directory. |
| #1603 | Snapshot boundary | Apply the same trusted-root and full-plan validation to snapshot install, backup, and export before any filesystem mutation. |
| #1604 | Project metadata boundary | Route config deletion and project lockfile writes through regular-file and canonical trusted-root guards. |
| #1606 | Hardlink boundary | Reject hard-linked write destinations and virtualenv files before they can mutate an inode outside the trusted project root. |

## Implementation Plan

1. Replace synchronous preflight probes with bounded asynchronous subprocess checks, clear completed timers, and default to Codex/OMX descriptors.
2. Normalize update preservation paths against a stable destination root and retain protected-file baselines across partial and repeated updates.
3. Make dry-run configuration loading and update orchestration side-effect free while preserving the calculated change plan.
4. Record component execution errors separately from version skips and propagate failures through init and batch CLI contracts.
5. Emit compact outcome JSONL, retain tolerant legacy parsing, and update collection for Codex-first ingestion, idempotent database writes, deduplication, and diagnostics.
6. Validate public updater paths before reads or writes and stage update application so invalid or failed plans do not leave partial changes.
7. Prevalidate snapshot import/export, backup, MCP virtualenv, doctor-repair, config-delete, and project-lock plans through the same canonical trusted-root primitives before the first mutation; reject hard-linked destinations and cross-operation overlap.
8. Promote changelog and release metadata to v1.0.8, then run targeted and full release verification.
