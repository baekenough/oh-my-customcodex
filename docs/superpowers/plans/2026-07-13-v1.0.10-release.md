# v1.0.10 Release Plan

## Goal

Make native GPT Codex and OMX discovery the enforceable package contract: install deterministic TOML roles, install and preserve the root Codex hook registry, prove complete project-scoped OMX readiness, and fail closed when those regressions break in merge or release workflows.

## Release Unit

| Issue | Priority | Scope | Outcome |
| --- | --- | --- | --- |
| #1590 | P1 | Native agents/Web UI | Compile packaged Markdown sources into deterministic managed TOML roles, preserve custom and OMX ownership, and move active Web surfaces to native roles. |
| #1591 | P1 | Native Codex hooks | Convert compatibility hooks into the root Codex discovery schema, normalize real tool payloads, and merge shared ownership safely. |
| #1592 | P1 | OMX readiness | Validate the full project-scoped plugin, launcher, manifest, assets, agents, skills, hooks, and guidance contract rather than binary presence. |
| #1618 | P1 | CI/release gates | Run the synchronized native regression inventory in fail-closed merge and release batches. |
| #1619 | P1 | OMX launcher integrity | Reject plugin hook registries that do not invoke the exact packaged OMX launcher command. |

## Constraints

- Preserve parent-package behavior and package shape while changing only the provider boundary from Claude-native discovery to GPT Codex plus OMX.
- Keep packaged Markdown agent definitions as authoring and Claude-compatibility inputs; native TOML roles are the active Codex runtime surface.
- Preserve custom and OMX-owned roles and hook handlers during managed merges.
- Keep npm and GitHub Packages artifacts equivalent and versioned from the same source tree.
- Treat #1610 as an open upstream OMX dependency: this release mitigates harness-owned setup flows but does not claim repeated external `omx setup` ordering is fixed.
- Use `omcustomcodex` in commands and documentation.

## Implementation

1. Compile package-managed Markdown agents into canonical native TOML roles with deterministic naming, metadata, collision handling, and ownership-aware merges.
2. Move CLI diagnostics and the Web UI agent list/detail/create/count surfaces to the native TOML contract with path and symlink confinement.
3. Convert compatibility hook definitions into the root Codex hooks schema, normalize real Codex tool payloads, and preserve shared Codex/OMX handlers.
4. Re-normalize shared hooks after harness-owned OMX setup and update flows as a local #1610 mitigation.
5. Model OMX readiness as a complete project-scoped contract covering source, manifest, assets, launcher identity, agents, skills, hooks, and generated guidance.
6. Keep doctor, list, security, installer, updater, and package verification outputs consistent with the same native contract.
7. Maintain one synchronized critical-test inventory and execute every batch fail closed in both CI and release workflows.

## Verification

- Focused native-agent, Codex-hook, OMX-readiness, doctor, CLI, Web, and workflow guard suites.
- Svelte validation, Biome lint, root/eval-core TypeScript checks, and `git diff --check`.
- Full `bun test tests/ packages/eval-core/` with zero failures.
- `bun run build`, source-lock semantic stability, version sync, template sync, docs validation, and `bun run verify:package`.
- Isolated packed-tarball install using OMX 0.20.1 and Codex 0.144.1, including native role count, hook registry shape, and doctor smoke checks.
- Independent verification of non-zero Bun exits in CI/release helpers, including failure before later batches can run.
- PR checks green, merge to `develop`, tag `v1.0.10`, npm/GitHub Packages publication, GitHub Release, issue/milestone closure, and registry install smoke (R020).

## Stop Condition

The release is complete only when npm and GitHub Packages both expose `1.0.10`, the tag and GitHub Release exist, a clean registry install passes native agents/hooks/doctor smoke checks, #1590, #1591, #1592, #1618, and #1619 plus the v1.0.10 milestone are closed, #1610 remains truthfully open as an upstream dependency, and the remote release branch is removed.
