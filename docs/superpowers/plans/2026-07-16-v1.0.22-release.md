# v1.0.22 Release Plan

## Goal

Ship `v1.0.22` from the `v1.0.21` package baseline for milestone #27. Record
the OpenAI Codex `rust-v0.144.4`/`rust-v0.144.5` tagged final state, raise the
required oh-my-codex runtime floor to `0.20.2`, and preserve the provider
boundary instead of copying Codex or OMX runtime behavior into this package.

## Pinned Release Unit

| Issue | Upstream release | Planned outcome |
| --- | --- | --- |
| #1641 | OpenAI Codex `rust-v0.144.4` | Record that the official note says no user-facing changes while the divergent tagged ancestry includes release-branch projection `d82b7e5d4c` of PR #32875: Guardian uses the selected model's `ModelMessages.auto_review.policy`, with precedence `guardian_policy_config` -> catalog policy -> built-in fallback. |
| #1663 | OpenAI Codex `rust-v0.144.5` | Record expanded dangerous-command detection for forced `rm` forms and clearer denial reasons as external Codex safety behavior. |
| #1664 | oh-my-codex `v0.20.2` | Raise `MINIMUM_OMX_VERSION` from `0.20.1` to `0.20.2` and document the cumulative role-routing, child-stop, Ralplan, session-provenance, `AGENTS.md` merge-policy, and foreign-hook-coordinate fixes. |

## Mode and Dependency Order

- Use **standard mode**; no expedited-release or verification waiver applies.
- Required graph: `#1641 -> #1663`. Establish the `0.144.4` release-note/tag
  divergence and Guardian final state before appending the `0.144.5` cumulative
  safety state.
- Execute #1664 in parallel with the Codex documentation lane. Converge both
  lanes before metadata promotion, package verification, or release publication.

## Constraints

- Preserve the provider boundary. The only package-owned runtime change is the
  OMX minimum-version constant and its existing install/update/doctor consumers.
- Do not add a Codex minimum-version gate, Guardian implementation, selected-model
  catalog, `guardian_policy_config`, dangerous-command classifier, denial policy,
  role router, SubagentStop behavior, Ralplan bootstrap, or OMX setup engine.
- Treat official release notes and tagged ancestry as separate evidence. Do not
  collapse the `rust-v0.144.4` divergence into a no-op conclusion.
- Describe upstream #3151 as resolving `Yeachan-Heo/oh-my-codex#3147` in
  `v0.20.2`; retain the bounded `omcustomcodex` normalization as defense in depth.
- Keep `guides/openai-codex/01-version-compatibility.md` and its installed
  template byte-identical, and refresh the wiki summary/hash only after content
  settles.
- Add no dependency and do not redesign install, update, doctor, readiness,
  plugin, configuration, or package layout.
- Keep dry runs side-effect-free and keep unparseable OMX version output
  fail-closed. Existing SemVer and API-readiness behavior must not regress.
- Defer `1.0.22` version promotion and generated metadata refresh until all
  implementation lanes are green.

## Rollback

- Before auto-tag publication, stop the release and add a normal `git revert` on
  the release branch or `develop` as appropriate; keep `v1.0.21` current and
  leave the issues/milestone open with failing evidence attached.
- After auto-tag starts, stop/cancel downstream workflow work when authorized,
  reopen any provisionally closed issues and milestone, and fix forward as
  `v1.0.23`. Do not delete or reuse `v1.0.22` by default because publication may
  be racing or partially complete.
- Deleting a tag/GitHub Release and reusing `v1.0.22` is prohibited unless both
  registries are authoritatively proven unpublished **and** a maintainer gives
  explicit approval for the destructive recovery. After either registry
  publishes, never reuse the version; deprecate if necessary and fix forward.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| The `0.144.4` “no user-facing changes” note hides tagged behavior. | Verify release notes and tag ancestry independently and preserve the divergent comparison plus `d82b7e5d4c` evidence. |
| Guardian precedence is misstated. | State selected Guardian model `ModelMessages.auto_review.policy` with `guardian_policy_config` first and the built-in policy last; identify `d82b7e5d4c` as tagged release-branch projection evidence rather than the PR merge commit, and add no local policy. |
| Codex dangerous-command behavior is duplicated and drifts. | Document it as provider-owned and keep all local classifier/source changes out of scope. |
| `0.20.1` remains accepted through a stale fixture or consumer. | Make `0.20.1` the explicit stale boundary across unit, integration, snapshot, E2E, update, install, and doctor coverage. |
| #3147 is described as unresolved after #3151 ships. | Verify `v0.20.2` ancestry and update both current guide and wiki language while preserving historical context. |
| Smoke installation mutates the developer machine. | Pin `oh-my-codex@0.20.2` and isolate HOME, npm prefix, and PATH under one temporary root. |
| Guide, template, wiki hash, plugin version, or package metadata drift. | Settle content once, verify linked-worktree build idempotence, then generate the committed lock in a fresh standalone checkout with zero explicit root fields and run parity, version-sync, wiki, docs, build, and `verify-package-contract.mjs --skip-build` gates. |
| Registry eventual consistency causes a false completion claim. | Poll exact versions through authoritative npm/GitHub APIs and require clean installs plus the GitHub Release before closing milestone #27. |

## Acceptance / Stop Condition

The release is complete only when `v1.0.22` is built from the `v1.0.21`
baseline; OMX `0.20.1` is rejected and `0.20.2` is accepted across install,
update, doctor, and readiness paths; the exact isolated `oh-my-codex@0.20.2`
smoke passes; Codex `0.144.4` divergence/Guardian precedence and `0.144.5`
dangerous-command behavior are documented as external; no local Codex floor or
provider implementation is added; source/template/wiki/generated metadata agree;
all focused and full gates pass; and the PR, CI, tag, npm package, GitHub Package,
GitHub Release, issues #1641/#1663/#1664, and milestone #27 are verified through
R020 evidence.
