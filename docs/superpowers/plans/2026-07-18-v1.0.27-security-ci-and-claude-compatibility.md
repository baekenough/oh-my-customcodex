unresolvable base/head, a Git error, or an unclassified path means full CI.
The only fast-path candidates are static Markdown changes entirely within:

```text

CHANGELOG.md

```

```text

```

Keep every required job present. Gate only selected expensive internal steps;
do not use job-level skipping that makes required checks disappear. Package
contract, documentation validation/build, version sync, template sync, Wiki
sync, and Security Audit remain mandatory. Any release version/metadata change
therefore runs full CI.

### #1677 — serialized, recoverable triage acknowledgment

Add workflow-level concurrency keyed by workflow name and issue number with
`cancel-in-progress: false`. Do not add an unsupported `queue` field. Read the
latest label state fail closed, and use a stable hidden acknowledgment marker in
the issue comment:

1. If `triaged` is present, exit without comment or label mutation.
2. If `triaged` is absent and the marker is absent, post one marked comment,
   then add `triaged`.
3. If the comment succeeded but the label mutation failed, a retry sees the
   marker and adds only the missing label.
4. If comment/label reads or mutations fail, propagate failure; do not infer a
   safe state from missing output.

The existing `issues: [opened, labeled]` trigger remains. Serialization reduces
same-issue overlap; marker readback makes partial success and retries
idempotent.

## RED-First Parallel Execution

All source changes occur in the shared release worktree, but primary ownership
is disjoint. No lane edits another lane's files. Begin with a short RED barrier:
Lane A writes its semantic tests; Lane B writes all workflow tests; Lane C
captures the current failing Bun audit and may inspect the dependency graph but
does not edit the Security Audit workflow until Lane B confirms its RED
assertion. After that barrier, the three GREEN lanes run in parallel.

No lane runs global build, plugin synchronization, canonical source-lock
generation, release version mutation, changelog mutation, or final Wiki hash
generation. The integrator runs those operations once after all lanes join.

## Failure Recovery and Non-Goals

- A classifier ambiguity, Git error, missing base, or unsafe path always falls
  back to full CI; never expand the allowlist to make a test pass.
- A Security Audit failure blocks the release. Do not restore npm-lock fallback,
  ignore advisories, suppress stderr, add `|| true`, or replace the audit with a
  help-only command.
- Do not mechanically copy parent Claude runtime behavior, change provider
  minimum versions, add hooks, or claim native Codex implements Claude fixes.
- Do not add new package names or direct dependencies. The approved dependency
  work is limited to the exact existing-package versions and transitive
  `picomatch` override above.
- Do not fully regenerate `bun.lock`, accept unrelated dependency churn, create
  a new workflow-test file, or let parallel lanes write the same file.
- Do not hand-edit generated plugin metadata, repeatedly regenerate Wiki/source
  locks while lanes are active, or run a global build before the join.
- Before merge/tag, repair on `release/v1.0.27` and rerun affected gates. If
  automation provisionally closes issues/milestone but publication fails,
  restore lifecycle state before a new attempt.
- Once either registry publishes `1.0.27`, never delete/reuse its version or
  tag. Preserve evidence and fix forward as `v1.0.28`.
- Do not force push, reset destructively, create/delete/move a tag manually,
  publish manually, or close issues/milestone manually when repository
  automation owns those transitions.
