# v1.0.16 Release Plan

## Goal

Raise the packaged OMX runtime floor to the cumulative `v0.20.1` final state and
record the OpenAI Codex `rust-v0.143.0` through `rust-v0.144.3` compatibility
disposition without copying provider-owned runtime behavior into this child
package.

## Constraints

- Preserve the provider boundary: this package records compatibility and enforces
  an installed-runtime floor; it does not implement OMX or Codex runtime
  features locally.
- Accept an OMX version only from product-anchored `oh-my-codex v...` output or
  an exact bare semver line. Unrelated version text must not satisfy the floor,
  and unparseable output remains fail-closed as `unknown-version` even when
  `omx api` is available.
- Use the final released state rather than repeating superseded intermediate
  behavior. In particular, do not present the `rust-v0.144.0` Guardian prompt
  update as current after the `rust-v0.144.2` rollback.
- Treat official release notes and Git tag ancestry as distinct evidence. The
  `rust-v0.144.3` note says version-only, while the tagged ancestry also contains
  direct commit `8a4d35a` for the advanced reasoning picker.
- Keep #1610 open: OMX `v0.20.1` still has the direct `omx setup` positional hook
  reorder defect tracked upstream as `Yeachan-Heo/oh-my-codex#3147`; the child
  harness only retains its bounded normalization mitigation.
- Keep the guide source and installed template byte-identical.
- Add no runtime dependency and do not change provider-owned configuration or
  plugin layout in this release.
- Enforce the OMX floor after a non-dry update even when project files are
  already current, but keep dry runs entirely free of runtime installation or
  upgrade side effects.
- Defer package-version promotion and generated lock/hash refresh until the
  integrated release step.

## Non-Scope

- Reimplementing remote plugins, proxy discovery, MCP authentication/tool search,
  app-server APIs, Guardian, advanced reasoning UI, model catalogs, Team,
  Ralplan, Conductor, Stop hooks, capability locks, or plugin-mode setup.
- Claiming that the documented Codex/OMX capabilities are shipped by
  `oh-my-customcodex`; they remain properties of the installed upstream runtimes.
- Closing #1610 or removing its local mitigation before the upstream positional
  hook-merge defect and live Codex trust preservation are verified.
- Reopening closed monitor-only #1574. Its `rust-v0.144.1` installer/code-mode
  fixes are final-state context between the pinned `0.144.0` and `0.144.2`
  releases, not a release-unit issue.
- Changing guide, skill, rule, agent, hook, or workflow counts.
- Treating the snapshot `CODEX_HOME` isolation as a new product capability or
  expanding it beyond hermetic test setup.
- Adding dependencies, changing lockfile dependency resolution, or redesigning
  package/install/update/doctor flows beyond the version constant.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| Release-note-only review misses a direct tagged commit. | Preserve the explicit `0.144.3` release-note/tag-ancestry discrepancy and verify the tag comparison before closure. |
| Superseded Guardian behavior is documented as current. | Describe the cumulative final state and state that `0.144.2` restored the prior policy, request format, prompting, and tools. |
| An unrelated tool version is parsed as OMX, or a working API masks an unverifiable version. | Require product-anchored/exact-bare parsing and keep unknown version output fail-closed regardless of API availability. |
| Bun process-wide mocks make the version/API boundary test order-dependent. | Run the OMX installer boundary suite in a dedicated process in both stable CI and release gates. |
| An active FSD/OMX session leaks host `CODEX_HOME` configuration into snapshot readiness. | Set `CODEX_HOME` to the temporary test home explicitly and run the integration test as hermetic verification. |
| An already-current update skips the runtime floor, or a dry run mutates the host toolchain. | Enforce OMX after the non-dry no-op path, record failed-upgrade warnings, and guard all runtime installation checks behind `!dryRun`. |
| OMX release notes are mistaken for local implementation guarantees. | Use dependency/baseline language throughout and prohibit source-level runtime claims. |
| #1610 is closed because `0.20.1` sounds cumulative. | Name the still-open direct-setup defect and upstream #3147 in the guide, wiki, plan, and release review. |
| Source/template or derived metadata drifts. | Copy once, verify byte parity, then regenerate `.omcodex.lock.json` and `wiki/.source-hashes.json` only after final content/version promotion. |

## Stop Condition

The release is complete only when the package rejects OMX `0.20.0`, accepts
`0.20.1`, rejects unrelated or unparseable version output even when the API
exists, the focused boundary suite runs in a dedicated process in both stable
CI and release gates, an already-current non-dry update still enforces the floor
and records a failed-upgrade warning while dry-run remains side-effect-free,
snapshot readiness runs in a dedicated stable batch and rejects a decoy ambient
`CODEX_HOME`, the installed compatibility guide matches its source byte-for-byte, Codex
`0.143.0`-`0.144.3` and OMX `0.19.1`-`0.20.1` are documented as cumulative
external-runtime final states, Guardian rollback and the `8a4d35a` ancestry
discrepancy are explicit, #1610 remains truthful, derived metadata is refreshed,
and all seven pinned issues plus the external `v1.0.16` release outcomes are
verified.
