# v1.0.9 Release Plan

## Goal

Make the published package contract truthful and usable from clean npm and GitHub Packages installs, including the shipped Web UI and linked-worktree development hooks.

## Release Unit

| Issue | Priority | Scope | Outcome |
| --- | --- | --- | --- |
| #1583 | P1 | Package/Web runtime | Build and ship the production Web server, then prove packed `web start/status/stop` and representative routes. |
| #1584 | P1 | Node/library contract | Align Node engines, declarations, exports, package-root resolution, and `VERSION` with the actual tarball. |
| #1608 | P2 | Codex/OMX worktrees | Install Git hooks through Git-native paths in normal checkouts and OMX Team linked worktrees without false-success output. |

## Constraints

- Preserve the v1.0.8 filesystem-boundary hardening while integrating the package-root fix.
- Do not add a runtime dependency solely to hide declaration leaks; keep test-injection types structural and public-consumer-safe.
- npm and GitHub Packages must use the same built artifact set.
- Keep the package name split intact: `oh-my-customcodex` on npm and `@baekenough/oh-my-customcodex` on GitHub Packages.
- Use `omcustomcodex` in commands and documentation.

## Implementation

1. Extend the root release build to emit public declarations and the `packages/serve` production build.
2. Include the Web build in the package allow-list and bundle its route dependencies.
3. Replace depth-based package-root discovery with package-metadata discovery for both registry names.
4. Source public `VERSION` from package metadata.
5. Advertise only Node lanes supported by every clean-installed production dependency.
6. Add a clean packed-consumer verifier covering artifact paths, dependency engines, ESM, strict TypeScript, and Web lifecycle/routes.
7. Run the verifier in PR CI and before release artifacts are uploaded.
8. Resolve Git hook directories with Git rather than assuming `.git` is a directory, and test checkout/worktree/non-Git behavior.

## Verification

- Targeted unit tests for package metadata, package-root discovery, updater declaration boundaries, and hook setup.
- `bun run typecheck` and eval-core typecheck.
- Biome lint and `git diff --check`.
- `bun run verify:package` from a clean build.
- Full `bun test tests/ packages/eval-core/`.
- `bun run build` plus version, template, wiki, and documentation sync gates.
- Independent code review with no unresolved P1/P2 findings.
- PR checks green, merge to `develop`, tag `v1.0.9`, npm/GitHub Packages publication, GitHub Release, issue/milestone closure, and registry install smoke (R020).

## Stop Condition

The release is complete only when both registries expose `1.0.9`, a clean registry install passes CLI/library/Web smoke checks, all scoped issues and the v1.0.9 milestone are closed, and the release branch is removed remotely.
