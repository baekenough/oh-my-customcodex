# v1.0.15 Release Plan

## Goal

Remove the remaining Claude-native assumptions from installed Codex guidance,
status surfaces, and ontology discovery while making the package identity
consistent across Bun and npm metadata.

## Release Unit

| Issue | Outcome |
| --- | --- |
| #1594 | Invoke installed skills through `$skill-name` or `/skills`, and distinguish harness Markdown policy from native Codex `.rules` execution policy. |
| #1596 | Stop installing Claude `statusLine` JSON and stdin scripts into `.codex`; use the native Codex/OMX status surface and migrate only harness-owned legacy artifacts. |
| #1597 | Discover `.codex/ontology` first, validate explicit paths, and retain `.claude/ontology` only as an explicit compatibility fallback. |
| #1617 | Align the Bun root workspace identity with `oh-my-customcodex` and detect future package/lock drift deterministically. |

## Constraints

- Preserve existing user-authored config and custom status commands.
- Keep Claude assets only at explicit compatibility/template boundaries.
- Do not move behavioral Markdown policy directories in this release; label and
  load them truthfully instead.
- Preserve `.codex/config.toml` byte-for-byte while removing dead JSON config.
- Add no runtime dependency.
- Keep package and template versions synchronized at `1.0.15`.

## Parallel Ownership

1. #1596: installer/updater migration and focused TypeScript regression tests.
2. #1597: ontology-rag discovery, validation, diagnostics, and Python tests.
3. #1594: README/AGENTS/list/doctor policy naming and explicit skill invocation tests.
4. #1617 plus release integration: Bun lock identity, package verifier, version,
   changelog, aggregate validation, PR, and publication.

## Verification

- Focused tests for each issue lane.
- Official Codex manual contract: `$skill-name`/`/skills`, `[tui].status_line`,
  and `.rules` command policy semantics.
- `bun install --frozen-lockfile`, lint, typecheck, full tests, Svelte check,
  production build, documentation validation, and packed package contract.
- CI green; tag and both package registries verified; all four issues and the
  v1.0.15 milestone closed.

## Stop Condition

The release is complete only when a clean install exposes native skill guidance,
does not create Claude status-line files under `.codex`, resolves Codex ontology
without MCP-only environment coupling, reports one package identity across npm
and Bun, and the external release outcomes are verified.
