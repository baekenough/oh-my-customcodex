## Release-Target Resolver Contract

Add scripts/resolve-release-target.mjs as the single deterministic resolver.
Freeze its CLI contract before parallel lane work begins.

Inputs:

- package name, default oh-my-customcodex;
- scoped package name, default @baekenough/oh-my-customcodex;
- repository root;
- authenticated GitHub Packages access;
- optional injected Git, public npm, and GitHub Packages data for tests;
- JSON output mode.

Read-only live probes:

~~~bash
git tag --list 'v*'
npm view oh-my-customcodex version --json
npm view oh-my-customcodex versions --json
gh api '/users/baekenough/packages/npm/oh-my-customcodex/versions?per_page=100'
~~~

Rules:

1. Parse only strict stable x.y.z versions. Ignore prereleases when calculating a
   stable patch target.
2. Calculate gitLatest, npmLatest, and ghpLatest independently. Choose the
   greatest stable value across all three as baseVersion and increment patch
   once.
3. Confirm targetVersion is absent from Git tags, public npm versions, and the
   authenticated GitHub Packages version list.
4. Treat public npm or GitHub Packages authentication, network, parse,
   pagination, or unexpected empty-response failures as blocking. Never silently
   fall back to Git, another registry, or memory.
5. Accept first-release absence only after the registry itself is reachable and
   an authenticated package-list query succeeds while proving the package is
   absent. A bare 404, auth failure, or ambiguous empty result is not absence.
6. Paginate GitHub Packages until exhaustion before calculating ghpLatest or
   proving target absence.
7. Emit one JSON record containing measuredAt, packageName, scopedPackageName,
   sourceSha, gitLatest, npmLatest, ghpLatest, baseVersion, targetVersion,
   per-source probe status, absence checks, and warnings.
8. Never mutate tags, milestones, issues, labels, branches, packages, or files.
9. Session memory is an advisory comparison only. A mismatch produces a warning
   but never changes the measured result.

The expected target is 1.0.24 only if the fresh authenticated three-source
measurement still returns a maximum stable version of 1.0.23. Milestone #29
cannot override a different resolver result.

## External-Mutation Evidence Barrier

Restructure auto-dev so no professor-triage execution or GitHub mutation occurs
before a reviewed evidence barrier.

### Phase A: parallel read evidence

Allowed operations are fresh fetches and read-only queries:

- tags, HEAD, branches, public npm, authenticated GitHub Packages, milestones,
  labels, issues, dependencies, release-monitor queues, PRs, and workflows;
- current files, tests, and previous local artifacts.

Do not invoke the professor-triage skill or
.github/scripts/analyze-issue.ts in this phase: both include or lead to GitHub
write behavior. No gh label create, gh issue edit/comment/close, assignment,
milestone mutation, PR creation, release mutation, publish, or tag mutation is
allowed.

### Phase B: read-only triage draft

Add an explicit triage-draft prompt step. It invokes native explore subagents for
repository mapping and a local synthesis prompt using the read-only rubric from
professor-triage. It does not invoke the professor-triage skill.

Write a local JSON draft under the normal session artifact path. The draft
contains:

- evidence source and timestamp;
- exact issue number and current state;
- proposed priority, labels, assignment, regular non-symlink comment body-file
  path, exact body byte length and lowercase SHA-256 digest, close/no-close
  decision, milestone action, and rationale;
- expected precondition values used for compare-and-set readback;
- no executable shell or embedded long Markdown.

The release-plan and deep-plan skills may consume this read-only draft because
they do not apply GitHub changes. If either proposes a new mutation, regenerate
and review the draft before proceeding.

### Phase C: evidence join and review

Wait for every parallel read lane. Join target resolver JSON, issue evidence,
dependency order, milestone lookup, and the triage draft. A partial or mid-step
subagent response cannot satisfy this barrier.

Stage long Markdown and JSON through scripts/safe-command-payload.mjs. Review the
complete local mutation draft. If any query is missing, stale, or contradictory,
return to Phase A.

### Phase D: mutation commit and readback

Add scripts/apply-triage-draft.mjs and invoke it only from mutation-commit after
Phase C passes:

~~~bash
node scripts/apply-triage-draft.mjs   --draft "$TRIAGE_DRAFT"   --repo baekenough/oh-my-customcodex
~~~

The script validates the schema and preconditions, then applies only reviewed
comment, label, close, assign, and milestone operations idempotently. Every
write is followed by a direct gh readback compared with the draft. Existing
matching state is success; contradictory state is a blocking drift failure.
Before the first write it validates each issue's sequential precondition chain;
when a comment and update share one observed snapshot, the comment precedes the
update so the draft cannot partially mutate and then fail on a stale comment.
The script never invents an action or edits the draft.

The normal professor-triage skill is not invoked in this release auto-dev path.
Its analysis rubric is reused read-only; the checked-in apply script owns the
reviewed Phase 5 mutation semantics.

Structural tests must parse every pre-barrier workflow step and prove zero
mutation commands, zero professor-triage skill invocations, and zero calls to
analyze-issue.ts. This includes direct gh writes, gh api POST/PATCH/DELETE,
comment, label, close, assign, milestone, release, and publish commands.

Implementation, PR creation, merge, and release remain later mutation phases,
but each uses the same draft then write then direct-readback discipline.

### C5. Canonical release verifier architecture

Add scripts/verify-release-contract.mjs with shared pure helpers in
scripts/release-evidence-lib.mjs. Freeze and test this CLI before Lane B wires

Permanent CI and release scripts must derive versions from package.json or the

Modes are intentionally separate.

#### Offline mode

“Offline” means release-state lookup offline, not air-gapped:

- it uses the local checkout and locally packed package version;
- it never queries current tags, npm latest/published target, GitHub Packages,
  GitHub Release, issues, milestones, PRs, or release workflow truth;
- normal declared dependency resolution may use configured registries;
- it accepts no release-registry or GitHub credential;
- fake command runners and local fixtures test all external-state branches.

The canonical offline verifier owns verify-package-contract exactly once as a
named subgate and always invokes `verify-package-contract.mjs --skip-build`.
Before that executable subgate, it must complete Git-index identity, selective
tracked-drift, untracked/ignored-sensitive, standard-root containment, tracked
entry-type/symlink, and version preflight. A preflight failure executes the
package verifier zero times and records package/alias gates as explicit
`SKIPPED` failures. On the valid path, the package verifier runs with an
allowlisted repository environment whose cwd remains the checkout but whose
HOME, USERPROFILE, CODEX_HOME, temp, npm userconfig/cache/prefix/public registry,
and Git config are isolated under the verifier execution root; it never inherits
the operator HOME or npmrc. It never starts a build itself. Every production
caller must complete and validate the required build immediately before invoking
the offline verifier.
CI and aggregate commands must not run verify:package immediately before or
after it. Later gates for the same source SHA validate and reuse the manifest
hash instead of repeating the package contract.

Required subgates:

1. requested/default version equals package, template, and generated plugin
   versions;
2. verify-package-contract runs once and its result/log is imported into this
   manifest;
3. production consumer installs omit --ignore-scripts and use isolated HOME,
   USERPROFILE, CODEX_HOME, npm cache, npm userconfig, prefix, cwd, and cleared
   NODE_PATH;
4. ignore-scripts resolves false for production consumers;
5. unscoped and scoped local artifacts have normalized file and package metadata
   parity;
6. CLI --version and --help pass;
7. ESM import returns the requested version and resolves templates without
   resolving checkout node_modules;
8. doctor exits cleanly without a stack trace in an isolated consumer;
9. foreign PreToolUse preservation passes;
10. canonical tracked-entry inventory and symlink preservation pass;
11. all required subgates are PASS; dependency skips after an explicit
    precondition failure remain visible and make the overall result FAIL;
12. a durable, safe manifest and per-gate logs exist even on ordinary failure.

The lifecycle sentinel is a separate synthetic fixture in
tests/verify-release-contract.test.js. It proves the npm runner executes a
harmless lifecycle script when ignore-scripts is false, but it is never injected
into either production package artifact or parity inventory.

Offline mode may accept canonical-lock-output. It may write that destination
only during the final post-build canonicalization step.

#### Live mode

Live mode runs only after publish and GitHub Release creation. The workflow uses
two process boundaries: a trusted credential-bearing prefetch step and a fresh
credential-free verifier process. It requires an exact dynamic version, exact
tag, repository, absent dedicated evidence directory, fixed live-input
directory, and --expected-source-sha.

The Release tag-push workflow passes the trusted workflow commit SHA as
--expected-source-sha. Before any npm, GitHub Packages, or GitHub Release query,
the trusted prefetch step peels the checked-out tag and compares it with that
SHA. It then uses `npm pack --ignore-scripts` to stage exactly one public and one
scoped tarball plus fixed JSON metadata, removes its authenticated npmrc, and
exits. The next step starts the verifier with no credential, Actions-token,
NODE_OPTIONS, auth-config, or module-resolution environment. The verifier peels
the tag again, validates the fixed input directory identity and tarball hashes,
then enables lifecycle scripts only for local-tarball consumers. A peel mismatch
fails before any registry probe or lifecycle execution.

Required subgates:

1. trusted expected source SHA is present;
2. tag peel equals expected source SHA;
3. the trusted no-script input proves public npm exposes exactly
   oh-my-customcodex@$VERSION;
4. authenticated GitHub Packages exposes exactly
   @baekenough/oh-my-customcodex@$VERSION;
5. GitHub Release for the exact tag exists;
6. each exact package installs in its own clean consumer root with lifecycle
   scripts enabled;
7. repository harness, unscoped consumer, and scoped consumer use three distinct
   cwd values; consumers also use distinct HOME, CODEX_HOME, cache, prefix, and
   userconfig and cannot resolve a sibling artifact;
8. NODE_PATH is removed and both consumers prove no checkout self-reference;
9. CLI, ESM, doctor, native hooks, foreign PreToolUse, and Web
   start/status/routes/stop checks pass for both; the detached Web server binds
   the explicit IPv4 loopback while the user-facing endpoint remains localhost;
10. normalized unscoped/scoped inventories and public metadata are equal except
    approved name and publishConfig differences;
11. evidence records exact specs, resolved versions, integrity where available,
    source SHA, and external URLs;
12. every required subgate is PASS.

Never fall back to latest, a local checkout import, or an unscoped artifact when
the scoped install fails.

### C6. Evidence schema, safety, and failure semantics

The safe evidence allowlist is:

- manifest.json
- subgates.json
- inventory-unscoped.json
- inventory-scoped.json
- parity.json
- tracked-entry-types.json
- external-state.json in live mode
- logs with stable non-secret filenames
- SHA256SUMS

manifest.json includes schemaVersion, mode, requestedVersion, tag, repository,
source SHA, timestamps, overall result, evidence_safe, gate counts, each gate's
duration/log/hash, tool versions, and evidence file hashes.

The verifier exits nonzero if a required gate fails, is skipped, references a
missing log, or produces unsafe evidence. A normal functional failure may still
produce evidence_safe=true and uploadable diagnostics.

Secret handling is fail-closed:

1. scan captured stdout, stderr, sanitized argv labels, thrown-error text,
   manifests, inventories, and logs before finalization;
2. evidence contains zero secret literals; replacements use the constant
   [REDACTED], never a token-derived value or hash;
3. evidence output must be an absent dedicated leaf outside repository, cwd,
   HOME, and filesystem-root identities; never recursively delete a pre-existing
   destination;
4. if any match remains, discard the private staging directory, create no upload
   directory, emit only a constant redacted summary, set evidence_safe=false,
   and fail;
5. never upload tainted evidence, even with if: always();
6. a missing referenced log makes the manifest invalid and fails the verifier.

Required named RED tests in tests/verify-release-contract.test.js:

- rejects symlink escape outside canonical root;
- rejects path prefix confusion between root and root-evil;
- rejects a symlinked evidence-dir;
- uses three distinct cwd values for repository, unscoped, and scoped commands;
- clears NODE_PATH and rejects checkout self-reference;
- redacts a token captured in stdout;
- redacts a token captured in stderr;
- redacts a token present in sanitized argv input;
- redacts a token included in thrown error text;
- stores zero secret literals and only constant [REDACTED] replacements;
- sets evidence_safe false and removes tainted upload evidence;
- fails when a manifest references a missing log;
- writes safe failure evidence and exits nonzero for an ordinary subgate failure;
- always invokes verify-package-contract with --skip-build and never starts a build;
- observes exactly two aggregate build invocations before final canonicalization.

## Auto Tag, Publish, and Live Verification

After merge:

1. Observe the Auto Tag workflow run whose headSha equals the recorded PR head
   SHA. Auto Tag is triggered from the merged PR context, so its run headSha is
   not the merge SHA.
2. Confirm Auto Tag creates annotated tag v1.0.24 whose peeled commit equals the
   PR merge SHA.
3. Confirm it provisionally closes the seven linked issues and milestone #29 and
   deletes release/v1.0.24.
4. Observe the tag-triggered Release workflow whose headSha equals the merge
   SHA/peeled tag commit.
5. Confirm npm publish, GitHub Packages publish, and GitHub Release creation.
6. Confirm live verification received trusted github.sha as
   --expected-source-sha and independently matched the peeled tag before any
   registry query.
7. Download evidence only when evidence_safe is true. Validate manifest hashes,
   overall PASS, failed 0, skipped-required 0, exact version 1.0.24, expected
   source SHA, and both registry specs.

Issue and milestone closure is provisional until the live verifier passes. If
publication or verification fails, fix forward. Do not delete or reuse a
published version. Reopen issues/milestone when closure would otherwise hide an
incomplete release.

## R020 Direct External Verification

Use direct queries after the workflow finishes:

~~~bash
gh pr view "$PR_NUMBER" \
  --json state,headRefOid,mergedAt,mergeCommit,statusCheckRollup,url

gh run list --workflow auto-tag.yml --limit 20 \
  --json databaseId,headSha,status,conclusion,url

gh run list --workflow release.yml --limit 20 \
  --json databaseId,headSha,status,conclusion,url

git fetch --tags --force
git cat-file -t v1.0.24
git rev-parse v1.0.24^{}
npm view oh-my-customcodex@1.0.24 version --json

gh api \
  '/users/baekenough/packages/npm/oh-my-customcodex/versions?per_page=100' \
  --jq 'map(select(.name == "1.0.24")) | first | .name'

gh release view v1.0.24 \
  --json tagName,isDraft,isPrerelease,publishedAt,url

gh issue view 1643 --json state,milestone
gh issue view 1646 --json state,milestone
gh issue view 1647 --json state,milestone
gh issue view 1662 --json state,milestone
gh issue view 1666 --json state,milestone
gh issue view 1668 --json state,milestone
gh issue view 1669 --json state,milestone

gh api repos/baekenough/oh-my-customcodex/milestones/29 \
  --jq '{state,open_issues,closed_issues,title}'

gh api repos/baekenough/oh-my-customcodex/branches/release/v1.0.24
~~~

The final branch query must return 404. Authenticate the Packages API through
the environment; never place a token in the command or artifact.

Download the release evidence artifact into a clean temporary directory. Verify
its allowlist, SHA256SUMS, manifest schema, and all subgate counts before
declaring success.

Final equality:

- recorded PR head SHA equals Auto Tag workflow run headSha;
- PR merge SHA equals peeled annotated tag SHA;
- peeled annotated tag SHA equals Release workflow run headSha;
- live verifier expected-source-sha equals the peeled tag SHA;
- npm and GitHub Packages both equal 1.0.24;
- GitHub Release tag equals v1.0.24;
- live consumers resolved exact 1.0.24 from their intended registries;
- evidence overall equals PASS with zero failed required gates;
- all seven issues are closed;
- milestone #29 is closed, open_issues 0, closed_issues 7;
- release branch is absent.

## Failure and Recovery Matrix

| Failure | Required response |
| --- | --- |
| Target resolver differs from 1.0.24 | Stop before mutation; re-measure and re-scope. |
| npm probe fails | Fail closed; do not infer from Git or memory. |
| Parallel evidence incomplete | Do not create labels, milestone, comments, or PR; return to join. |
| Draft differs from fresh GitHub state | Discard draft and re-run read phase. |
| Docs validator reports a stale claim | Fix the source claim; never suppress or return zero. |
| Offline verifier fails | Keep evidence, fix locally, rerun all affected gates. |
| Evidence contains a secret-like value | Fail, delete artifact, rotate if exposure is possible, fix redaction. |
| Symlink becomes a regular file | Fail canonical copy and lock generation. |
| Foreign hook changes or executes | Fail package contract. |
| Delegate stops mid-step | Measure local/external ground truth directly; resume only for missing work. |
| Auto Tag run headSha differs from PR head SHA, or tag peel differs from merge SHA | Stop release and investigate; never retag over published state. |
| One registry publish succeeds and the other fails | Preserve the published version and fix forward; never reuse it. |
| Live verifier fails after issue closure | Treat closure as provisional; reopen or clearly track fix-forward. |
| Deploy Test remains inactive | Expected by parent final behavior; rely on active packed-contract and live verifier. |

## Done Report

The final report must include:

- PR URL, recorded PR head SHA, and merge SHA;
- annotated tag object and peeled SHA;
- Auto Tag run URL/headSha and Release run URL/headSha;
- npm, GitHub Packages, and GitHub Release exact values;
- live evidence artifact name, manifest hash, and subgate totals;
- seven closed issue numbers;
- milestone #29 closed counts;
- release branch absence;
- changed-file summary by lane;
- explicit statement that deploy-test was intentionally not activated because
  the parent reverted that path;
- any residual risk or verification gap.

Do not report “done” from a delegated verdict, a command exit hidden by a pipe,
a registry latest value without exact version, or an evidence artifact that was
not downloaded and verified.
