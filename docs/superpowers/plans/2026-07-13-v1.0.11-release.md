# v1.0.11 Release Plan

## Goal

Make the installed harness truthful at every GPT Codex and OMX project boundary: explicit hook trust, authoritative linked-worktree assets, executable-body security, transactional snapshots, active-only hook packaging, and live doctor results.

## Release Unit

| Issue | Priority | Outcome |
| --- | --- | --- |
| #1611 | P1 | Require user-level hooks enablement and explicit live Codex approval; never manufacture effective trust in project configuration. |
| #1612 | P1 | Copy every required Codex/OMX surface transactionally, verify readiness, generate the final lock, and roll back exactly on failure. |
| #1613 | P1 | Use the authoritative main checkout for standard linked worktrees without crossing separate or nonstandard repository boundaries. |
| #1614 | P1 | Reject dangerous behavior in executable hook bodies, wrappers, command strings, substitutions, sourced scripts, and environment mutations. |
| #1615 | P2 | Ship and report only the five scripts reachable from the native Codex hook registry. |
| #1616 | P1 | Re-run live doctor checks after fixes modify shared OMX surfaces. |

## Constraints

- Preserve parent-package behavior and package shape while making GPT Codex plus OMX the active provider boundary.
- Do not auto-trust project hooks or write approval hashes on behalf of Codex users.
- Promote hook assets only for a content-verified standard linked worktree; fail closed for ambiguous layouts.
- Preserve byte content, entry type, and POSIX mode during snapshot rollback.
- Publish equivalent npm and GitHub Packages artifacts from one synchronized source tree.
- Use `omcustomcodex` in operator guidance.

## Implementation

1. Resolve the effective project root from Git topology and tracked-content identity, preserving the requested linked-worktree cwd for Codex execution.
2. Assess hook readiness from the live user feature flag and explicit approval state, with atomic compare-and-swap cleanup for stale trust metadata.
3. Parse native hook commands and executable bodies fail-closed through supported shell wrappers and confinement-sensitive mutations.
4. Restrict installed compatibility scripts to the active native registry footprint.
5. Wrap snapshot mutation in a complete transaction and validate both readiness and the final generated lock before commit.
6. Recompute doctor results after every repair instead of reusing stale findings.

## Stop Condition

The release is complete only when both registries expose `1.0.11`, the tag and GitHub Release resolve to the merged commit, a clean packed install confirms exactly five active native hook scripts, #1611 through #1616 and the v1.0.11 milestone are closed, and the remote release branch is removed.
