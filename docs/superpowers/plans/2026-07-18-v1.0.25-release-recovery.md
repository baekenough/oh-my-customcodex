# v1.0.25 Release Recovery Plan

## Goal and Stop Condition

Fix [#1671](https://github.com/baekenough/oh-my-customcodex/issues/1671)
with the smallest safe patch, carry forward the seven provisionally closed
`v1.0.24` issues, then publish `v1.0.25` through the repository-owned release
automation. The exact eight-issue release unit is #1643, #1646, #1647, #1662,
#1666, #1668, #1669, and #1671.

The existing annotated `v1.0.24` tag is immutable. Do not move, delete, replace,
or republish it. Run
[29645130553](https://github.com/baekenough/oh-my-customcodex/actions/runs/29645130553)
published no package and created no GitHub Release, so recovery is a new patch
release rather than a retry that changes historical state.

Auto Tag closed the seven `v1.0.24` issues and milestone #29 before publication
finished. Those closures are provisional because the Release workflow published
nothing. Preserve milestone #29 as the historical record of the failed
`v1.0.24` attempt, but use a fresh reviewed lifecycle draft to reopen those
seven issues and move them to milestone #30 (`v1.0.25`). Issue #1671 is already
open in milestone #30. The incomplete work is therefore tracked by #30 rather
than treated as delivered by #29.

The recovery is complete only when:

1. The `v1.0.25` PR has eight separate `Closes` lines, is green, and is merged
   to `develop`.
2. Auto Tag creates annotated tag `v1.0.25` at that merge SHA, closes all eight
   issues and milestone #30 at 0 open / 8 closed, and deletes
   `release/v1.0.25`.
3. The tag-triggered Release workflow completes Gate, Test, Validate
   Documentation, Publish, and Verify Release successfully.
4. npm and GitHub Packages expose exact version `1.0.25`, and the non-draft,
   non-prerelease GitHub Release exists.
5. Offline and live evidence manifests report `overall: "PASS"`,
   `evidence_safe: true`, zero failed gates, and valid checksums.

## Incident and Measured Baseline

Release run `29645130553` targeted merge SHA
`c6182a3f5a609dd16599373048e7335a93650b34`. Gate Release On CI and Validate
Documentation passed, but the macOS Test job ended with 111 passing and four
failing lifecycle-contract tests. Publish and Verify Release were skipped.

The Test job's `actions/setup-node` configuration included `registry-url`.
Setup Node therefore exported placeholder `NODE_AUTH_TOKEN` and
`NPM_CONFIG_USERCONFIG` values into a job that must be credential-free. The
offline verifier correctly rejects credential-name presence, so four fixtures
failed before reaching their intended boundary checks.

The seven issue closures associated with `v1.0.24` are publication-dependent,
not final delivery evidence. Milestone #29 records that failed release attempt;

verified.

## Minimal Fix Scope

1. In `.github/workflows/release.yml`, give the Test job only
   `permissions: contents: read`, set its checkout to
   `persist-credentials: false`, and remove `registry-url` only from its Setup
   Node step. Test must neither inherit the workflow's top-level write
   permissions nor persist checkout's Git `extraheader` credential. Keep the
   Publish and Verify Release permissions and authentication boundaries
   unchanged.
2. In `tests/unit/core/release-workflow.test.ts`, lock the workflow contract:
   Test has only read permission, disables checkout credential persistence, and
   contains neither `registry-url` nor `NODE_AUTH_TOKEN`; Publish keeps npm and
   GitHub Packages credentials, and Verify Release keeps its intentional
   authenticated prefetch.
3. In `tests/verify-release-contract.test.js`, pass an explicit empty `env` to
   fixture-mode cases that test filesystem or ordinary subgate failures. These
   fixtures must not inherit unrelated runner credentials.
4. Promote the normal release metadata from `1.0.24` to `1.0.25`, regenerate
   derived plugin and canonical lock artifacts through existing scripts, and
   record this recovery in the changelog and this plan.

Do not weaken production credential scanning, add secret values to tests, change
dependencies or `bun.lock`, alter publish scopes, retrigger publication from
`v1.0.24`, or remove credentials from jobs that actually publish or verify live
registries.

bump. Reproduce the runner condition with the same placeholder credential shape:

```bash

trap 'rm -f "$authrc"' EXIT

NPM_CONFIG_USERCONFIG="$authrc" \
  bun test tests/unit/core/release-workflow.test.ts \
```


drift. The offline verifier must finish with every gate passing and safe evidence;
the placeholder environment must not be present for that production verification.

Review the final diff against the allowlist. Within `release.yml`, allow only
the Test boundary changes: `contents: read`, `persist-credentials: false`, and
