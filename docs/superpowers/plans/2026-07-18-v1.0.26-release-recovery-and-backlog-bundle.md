# v1.0.26 Release Recovery and Backlog Bundle Plan

Publish `v1.0.26` as a fix-forward release from immutable `v1.0.25` and deliver
the reviewed four-issue backlog bundle:

- [#1657](https://github.com/baekenough/oh-my-customcodex/issues/1657) —
  provider-aware R017 cost reduction and rule ownership;

  remaining live broken references;
- [#1645](https://github.com/baekenough/oh-my-customcodex/issues/1645) —
  remaining skill invocation namespace mismatches.

Milestone #31 (`v1.0.26`) is the release owner. At the reviewed lifecycle
readback it is open with four open issues, all four issues are `OPEN`, assigned
to `baekenough`, retain their complete priority/quality label sets, carry
`in-progress`, and point to milestone #31.

The release is complete only when all of the following are true:

1. The four implementation contracts below pass targeted and full local
   verification at the final release head.
2. One `release/v1.0.26` PR contains four separate `Closes` lines, passes every
   required check, and merges to `develop`.
3. Repository automation creates annotated tag `v1.0.26` at that exact merge
   SHA; no human or local command creates, moves, or replaces the tag.
4. The tag-triggered Release workflow passes Gate, Test, Validate
   Documentation, Publish, and Verify Release, including a successful live
   checkout-credential gate using a POSIX-compatible regular expression.
5. Public npm, authenticated GitHub Packages, and the non-draft,
   non-prerelease GitHub Release expose exact version `1.0.26`.
6. The four issues are directly read back as closed, milestone #31 is closed
   with zero open issues, and the remote release branch is absent. GitHub may
   count the merged PR in `closed_issues`; direct issue states, not the aggregate
   closed count, are authoritative for the four-issue acceptance check.
7. Downloaded offline and live evidence artifacts have valid checksums,
   `overall: "PASS"`, `evidence_safe: true`, and no failed gate.

## Immutable v1.0.25 Incident

Release run
[29646261575](https://github.com/baekenough/oh-my-customcodex/actions/runs/29646261575)
targeted source SHA `04525a139d5052e3bf9a0d21ccc26c073e855c71` through annotated
tag `v1.0.25`. Gate Release On CI, Validate Documentation, Test, and Publish
succeeded. Publish created all three immutable release surfaces:

- public npm `oh-my-customcodex@1.0.25`;
- GitHub Packages `@baekenough/oh-my-customcodex@1.0.25`;
- published, non-draft, non-prerelease GitHub Release `v1.0.25`.

Verify Release then failed its live checkout-credential subgate. The verifier
passed this pattern to `git config --get-regexp`:

```text
^(http\..*\.extraheader|credential(?:\..*)?\.(?:helper|username|password|token))$
```

`git config --get-regexp` accepts POSIX extended regular expressions, not the
non-capturing `(?:...)` extension. Git therefore returned regex error exit 6;
the fail-closed gate correctly refused to treat it as the credential-absent
exit 1 result. The live evidence artifact remained safe, but its manifest
reported failure.

`v1.0.25` is already published and must remain immutable. Rerunning its workflow
would still execute the verifier committed at the `v1.0.25` tag and cannot
prove the corrected code. Recovery is therefore a new patch release. Do not
move or delete `v1.0.25`, replace its GitHub Release, or attempt to republish
either registry version.

## Parallel Implementation Plan

Write regression tests before changing behavior. The three lanes may run in
parallel because their primary source ownership is disjoint. No lane runs the
global plugin/lock regeneration while other lanes are editing; the integrator
runs generation once after all three lanes are joined.

### Lane A — Release Verifier and Lifecycle Payload

**Ownership**

- `scripts/verify-release-contract.mjs`
- `tests/verify-release-contract.test.js`
- `scripts/apply-triage-draft.mjs`
- `tests/apply-triage-draft.test.js`

**Work**

1. Replace only the non-POSIX grouping syntax in the Git credential pattern.
   Preserve the same credential key coverage and the gate's exit semantics:
   exit 1 means no matching local credential, exit 0 means a credential exists,
   and every other status or execution error fails closed.
2. Add real-Git fixture coverage for no match, a matching
   `credential.<url>.helper`, malformed-regex exit 6, and command execution
   failure. Assert the evidence log records exit status, match presence, and
   command error separately.
3. Build milestone API payloads from the already-normalized desired state. When
   `dueOn` is `null`, omit `due_on`; when non-null, preserve the exact ISO value.
   Do not change normalization or direct readback semantics.
4. Lock both null omission and non-null preservation in unit tests. No test or
   diagnostic command may issue a GitHub POST/PATCH.

**Acceptance**

```bash
bun test tests/verify-release-contract.test.js \
  tests/apply-triage-draft.test.js
```

The focused suite must prove the corrected POSIX expression through the actual
Git executable and prove the exact milestone request object without a network
mutation.

- Renaming intentionally plain skills such as `harness-eval` or
  `claude-native` to namespaced frontmatter names.
- Recreating already-removed profile guides/manifest profiles, tracked `dist/`
  output, stale hook paths, or other upstream-only findings already resolved in
  this child package.
- Tracking generated agent memory, inventing a new Codex memory field, or
  redesigning the memory backend.
- Removing defensive delegation guidance whose duplication protects a measured
  failure, or applying Claude-only spawn arguments to Codex native tools.
- Adding dependencies, changing package scopes, renaming registries, or changing
  release triggers.
- Manually creating a tag or GitHub Release, manually publishing a package, or
  manually closing the four issues/milestone after merge automation owns those
  transitions.
