## 목표

상위 `oh-my-customcode`의 검증된 위생 수정을 Codex + OMX 제공자 경계에 맞게 포팅하고, 네이티브 대체물이 없는 전략 제안은 명시적 비적용 결정으로 닫는다. 세 이슈를 하나의 patch 릴리스로 묶되, 동작 변경은 실측된 결함에만 제한한다.

## #1649 구현 범위

1. 구조화 개발 단계 파일을 `/tmp/.codex-dev-stage-$PPID`로 세션 스코핑한다.
   - reader: `stage-blocker.sh`, `task-state-precompact.sh`
   - writer/documentation: `structured-dev-cycle`, `MUST-orchestrator-coordination`
   - source/template/plugin 산출물 정합을 유지한다.
2. `session-autofix-prompt.sh` 등록을 `type: command`로 바로잡는다.
3. 상위에서 실행형으로 확정한 6개 훅 스크립트의 source/template/plugin mode를 `100755`로 통일한다.
4. `release.yml`과 동일 정책이 필요한 `ci.yml`의 `actions/cache`, `actions/upload-artifact`, `actions/download-artifact` mutable tag를 2026-07-19 GitHub tag ref가 가리키는 commit SHA로 고정한다.
5. `docs-sync.yml`의 실제 secret 이름을 주석에 반영하고, secret 미설정 시 이후 wiki-sync 단계가 실행되지 않도록 첫 단계 output 기반 조건을 건다.
6. 상위 v1.1.12에서 제거됐고 현재 tracked 참조가 없는 stale/orphan 자산을 삭제한다.
   - `.github/scripts/analyze-issue.ts`
   - `.github/scripts/notify-teammates.ts`
   - `scripts/sync-wiki.sh`
   - `scripts/sync-core.ts`
   - `.codex/ci-status.json.template`
   - `.codex/TODO.md` (완료 항목만 존재)

## #1649 비변경 판정

- `scripts/verify-version-sync.sh` 중복본은 포트에 존재하지 않는다. live `.github/scripts/verify-version-sync.sh` 단일본을 유지한다.
- `workflows/auto-dev.yaml`과 `templates/workflows/auto-dev.yaml`은 byte-identical이다. skill 내부 YAML은 별도 런타임 계약이므로 강제 동일화하지 않는다.
- qa-engineer wiki는 이미 문서형 페이지이며, 문제의 `autonomous-challenge-lessons` 경로는 포트의 가이드 구조에 존재하지 않는다.
- 가이드 진입문서 수는 상위의 57-guide 전제를 그대로 적용하지 않는다. 현재 wiki 검증과 포트 manifest 계약을 유지한다.
- tracked `.codex/outputs` 규약 위반 파일과 `measure-claude-mem-usage.sh`는 이미 없다.

## #1658 결정: 추가 포팅 없음

- 모든 규칙의 Claude 버전 노트는 현재 HTML comment로 숨겨져 있으며, Codex 진입문서 `AGENTS.md`는 약 1.5KB로 경량이다.
- 조항별 activation counter라는 신뢰 가능한 원천이 Codex/OMX에 없다. 추정 카운터로 규칙을 자동 은퇴시키면 상위 행동 계약을 비결정적으로 삭제한다.
- 따라서 이미 달성된 버전노트/진입문서 비용 절감은 유지하고, 자동 rule-retirement machinery는 제공자 경계와 상위 보존 원칙상 비적용으로 기록한다.

## #1659 결정: 기존 표면 보존

- 문제의 `profile` 스킬은 포트에 없다.
- 현재 OMX에는 이 저장소의 persisted YAML DAG/resume 의미를 대체하는 네이티브 Workflow surface가 없다.
- `$omcustomcodex:fsd`가 `omcustomcodex:loop`에 명시적으로 의존하므로 loop 은퇴는 현재 FSD 계약을 깨뜨린다.
- `sdd`/`sdd-development`는 의도적인 사용자 호출 alias이며, packaged skill은 직접 호출 가능하므로 텍스트 참조 0만으로 dead asset을 판정하지 않는다.
- 의미적으로 동등한 네이티브 대체물이 생기기 전까지 DAG/task/loop/alias 자산을 보존한다.

## 테스트 우선 순서

1. PPID-scoped marker가 scoped 파일만 차단하고 legacy global marker는 무시하는 회귀 테스트를 먼저 실패시킨다.
2. 훅 등록 type, 실행 mode, source/template/plugin 정합을 정적 테스트로 잠근다.
3. release/CI action SHA pin 및 docs-sync secret gate를 정적 테스트로 잠근다.
4. 제거 대상 6개 파일의 부재를 회귀 계약으로 잠근다.
5. 구현 후 targeted tests → lint/typecheck/build/package/offline contract → 전체 test → R017 순서로 검증한다.
