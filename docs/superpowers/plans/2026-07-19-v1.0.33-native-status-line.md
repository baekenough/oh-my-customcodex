# v1.0.33 Native Status Line Visibility Plan

## Release Target

Release **1.0.33** resolves #1694 without reintroducing Claude Code status-line
surfaces into the Codex target.

## Scope

1. Ensure a project-scoped OMX runtime receives a visible native Codex footer.
   OMX mirrors the project's `.codex/config.toml` into an isolated
   `CODEX_HOME`, so the project config must carry the native setting that the
   runtime consumes.
2. During project readiness provisioning, seed the default
   `[tui].status_line` only when no assignment exists. The default contains
   `model-with-reasoning`, `git-branch`, `context-remaining`,
   `total-input-tokens`, `total-output-tokens`, `five-hour-limit`, and
   `weekly-limit`.
3. Preserve any existing native assignment byte-for-byte, including custom
   item lists and the explicit opt-out `status_line = []`.
4. Retain the provider boundary: Codex init and update do not create
   `.codex/statusline.sh`, do not write Claude `statusLine` JSON, and do not
   configure `.codex/settings.local.json` as a footer surface.
5. Reuse the readiness installer's safe project-config boundary. Symlinked and
   hardlinked config files, identity races, and a config that disappears after
   a ready assessment fail closed instead of being followed, overwritten, or
   triggering setup from stale readiness. Required changes use a verified file
   descriptor with sync and exact readback so pathname swaps cannot redirect
   writes to another inode. Synchronous failures attempt exact rollback; the
   rewrite does not claim crash atomicity across termination or power loss.

## Acceptance Criteria

- A ready project with no `[tui].status_line` receives exactly one native
  default assignment, and a project-scoped OMX runtime mirror can consume it.
- An existing `[tui]` table receives the missing assignment inside that table
  without duplicating the table or changing unrelated bytes.
- A custom status-line assignment and an explicitly empty assignment are both
  left byte-for-byte unchanged.
- Repeated readiness provisioning is idempotent and never duplicates the
  assignment.
- Unsafe `.codex/config.toml` paths are rejected without mutating the linked
  target or reporting successful readiness.
- A config that disappears after the initial ready assessment fails without
  rerunning project setup.
- No Claude status-line script or settings JSON is generated under `.codex`.
- R012 continues to guarantee that project init and update do not overwrite
  user preferences; absence-only seeding supplies a fallback, not an
  ownership claim over an existing preference.

## Verification

- Add red/green unit coverage for missing config, an existing `[tui]` table,
  custom and explicitly empty assignments, idempotent reruns, and unsafe
  symlink/hardlink or replacement cases.
- Retain regression assertions that Codex targets do not receive
  `.codex/statusline.sh` or Claude `statusLine` JSON.
- Run the focused OMX-readiness and init/update tests, then lint, typecheck,
  the full test suite, build, documentation/template synchronization checks,
  and the package contract.
- Freeze one reviewed Git tree before release and verify the tag, GitHub
  Release, npm package, GitHub Packages artifact, issue closure, milestone,
  and remote release-ref cleanup against the immutable merge SHA.

## Risks and Controls

- **Preference overwrite:** treat every existing assignment, including `[]`,
  as authoritative and return without rewriting the file.
- **Invalid TOML placement:** insert into the existing `[tui]` table when one
  exists; otherwise append a single table and assignment using a
  format-preserving edit.
- **Filesystem redirection or race:** use the existing no-symlink,
  single-link, fingerprint, and parent-directory identity boundary. Write only
  through the verified config descriptor, sync and read it back exactly, and
  fail closed if the pathname stops identifying that inode. A path swap cannot
  redirect descriptor-bound writes to an external replacement. On synchronous
  failure, restore and verify the original bytes; surface uncertain recovery.
  Process termination and power loss remain outside the crash-atomicity claim.
- **Provider regression:** keep Claude compatibility assets isolated under
  their existing template boundary and never install them into `.codex`.

## Stop Condition

The exact v1.0.33 release tree passes all local and CI gates, #1694 closes via
release automation, both package registries and the GitHub Release read back
the immutable merge SHA, and the eligible issue/PR queues are re-enumerated.
