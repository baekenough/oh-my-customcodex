### #1680 corrected Codex boundary

The issue's initial hypothesis—that an outer `functions.exec` parser or a new
package-owned nested `exec_command` matcher must inspect Code Mode source—is
rejected by the official Codex `rust-v0.144.1` implementation:

1. `codex-rs/core/src/tools/code_mode/execute_handler.rs` parses and starts the
   Code Mode cell; it is not the nested shell-policy boundary.
2. `code_mode/delegate.rs` dispatches each nested tool promise back to the core
   turn host.
3. `code_mode/mod.rs` constructs the nested `ToolCall` and calls
   `ToolCallRuntime::handle_tool_call_with_source` with `ToolCallSource::CodeMode`.
4. `handlers/unified_exec/exec_command.rs:400-410` maps nested
   `exec_command({cmd})` to a `PreToolUsePayload` with Bash tool identity and the
   exact command string.
5. `registry.rs:495-538` runs PreToolUse hooks, applies block/rewrite results,
   and only then invokes the tool handler.
6. Official tests
   `pre_tool_use_rewrites_code_mode_nested_exec_command_before_execution` and
   `pre_tool_use_block_rejects_code_mode_tool_promise_before_execution` prove
   that rewrite/block occurs before the nested shell command executes.

Therefore the existing Bash-oriented managed advisor is the correct handler.
The missing boundary is activation/readiness: the captured local doctor
baseline `/tmp/v1028-doctor-baseline.log` reports both
`.codex/hooks.json native hook registry not found` and OMX `missing: native
hooks delivery`. A generic hook readiness result is not proof that the exact
reserved-variable advisor is runnable.

The second correction is result handling. In Code Mode, `tools.exec_command`
returns a JavaScript object containing `exit_code`; a running session has no
terminal exit code until its final poll. A JavaScript wrapper must inspect that
numeric field. It must not append `status=$?` after the test command, which
re-enters zsh's read-only `status` variable and can replace valid test evidence
with a wrapper failure.

## #1679 Durable Artifact Contract

### Canonical location and writer

The producer writes exactly one regular, non-symlink artifact per completed
deep-verify execution:

```text
.codex/outputs/sessions/YYYY-MM-DD/deep-verify-HHmmss.md
```

Add the contract helper at both source and install-mirror paths:

```text
.codex/skills/deep-verify/scripts/artifact-contract.mjs
templates/.claude/skills/deep-verify/scripts/artifact-contract.mjs
```

The files are byte-identical. The helper owns schema parsing/validation,
collision-safe writing, and deterministic selection through small testable
functions and `write`, `validate`, and `select` CLI subcommands. If the final
implementation keeps writing orchestration in `SKILL.md`, `validate` and
`select` remain mandatory and the same helper still owns the atomic regular-
file checks used before the producer rename.

The writer contract is:

1. Create the date directory without following a symlink outside the project.
2. Refuse a symlink/non-directory output root and a symlink, hard-linked, or
   pre-existing final artifact.
3. Write a same-directory exclusive temporary regular file, fsync/close it,
   validate the exact bytes, and rename atomically to the timestamped path.
4. On a same-second collision, fail explicitly or choose a deterministic unused
   suffix documented by the schema; never overwrite a previous review.
5. Read back and validate the final regular file before reporting success.
6. Never include credential values, complete environment dumps, or unredacted
   secret-bearing command output.

Directory and file safety is a continuous identity contract, not a one-time
`lstat`. Pin or re-correlate the project/session/date chain across every
critical `readdir`, open, publish, and readback so a concurrent directory ↔
outside-symlink swap cannot select an outside artifact or create an outside
file. Leaf reads use nonblocking, bounded fd I/O with path/fd identity and full
pre/post fingerprints; FIFO/socket/device inputs fail closed rather than hang.
The staged and final readback bytes must equal the exact serialized bytes, not
merely validate as some other schema-valid artifact.

`.codex/outputs/` remains ignored runtime evidence. The durable contract means
stable within the release worktree/session handoff, not committed release
source.

### JSON frontmatter schemaVersion 1

Every artifact begins with `---` delimiters containing exactly one JSON object.
JSON is YAML-compatible, but the dependency-free helper parses this block with
`JSON.parse`; YAML-only syntax is not accepted. Required fields:

```text
---
{"schemaVersion":1,"skill":"deep-verify","date":"2026-07-19T01:23:45+09:00","query":"release/v1.0.28","repository":"baekenough/oh-my-customcodex","releaseVersion":"1.0.28","verifiedSha":"<40 lowercase hex>","executionMode":"standard","verdict":"READY","findings":{"initial":[],"falsePositives":[],"fixed":[],"unresolved":[]},"verificationEvidence":[]}
---
```

`findings.initial` owns each full finding object once: stable `id`, severity,
summary, optional source location, and safe evidence. The three outcome buckets
contain references shaped as `{ findingId, reason, evidence }`. Every initial
id must appear in exactly one of `falsePositives`, `fixed`, or `unresolved`.
This preserves one stable lifecycle identity without duplicating the full
finding or allowing two terminal dispositions.

Validation requirements:

- reject an unknown schema version, missing or unknown required field,
  malformed ISO-8601 `date`, non-semver release, non-40-hex SHA, wrong skill,
  invalid verdict, invalid execution mode, non-array finding bucket, duplicate
  initial id, unknown outcome reference, or one id appearing in more than one
  outcome bucket;
- accept only `standard`, `docs-only-self-review`, `lite-deterministic`, and
  `converged-substitution` as `executionMode` values;
- resolve outcome severity and source location through the referenced initial
  finding; `falsePositives` and `fixed` therefore retain their original
  severity instead of disappearing from history;
- `verificationEvidence` records the gate name, observed outcome, and a safe
  evidence reference. It must distinguish not-run from pass;
- the Markdown body remains the human report and summarizes, but does not
  replace, the structured frontmatter. If the implementation validates body
  counts, it must define and emit one machine-readable
  `<!-- deep-verify-counts:{...json...} -->` marker; it must not infer counts
  from prose headings;
- `verdict` remains the existing deep-verify judgment rather than inventing a
  new severity policy. The selector reports unresolved findings exactly as
  recorded. A producer may report `READY` only after the artifact write and
  readback validate successfully; clean and blocked runs both still write an
  artifact.

### Deterministic selector and Source B

`select` accepts explicit repository, release version, and verified SHA. It
discovers only regular files under the canonical session tree whose basename
matches the deep-verify artifact convention.

Selection order and failure behavior:

1. Parse and validate candidates rather than trusting filenames or filesystem
   modification time.
2. Use the frontmatter `date` as the primary descending timestamp. Never use
   mtime as a recency signal.
3. Use normalized lexical path order as the deterministic tie-breaker.
4. Require exact `repository`, `releaseVersion`, and `verifiedSha` correlation.
5. Determine relevance from a successfully decoded JSON envelope before full
   schema validation. A candidate whose decoded repository/release/SHA matches
   but whose remaining schema is malformed participates in ordering and, when
   newest, fails closed. If any canonical candidate cannot be JSON-decoded,
   relevance and metadata time are unknowable without violating the no-mtime
   rule, so the entire selection fails closed; do not silently fall back to an
   older clean report.
6. If no artifact exists, only another release exists, the release version is
   wrong, or the SHA is wrong, return nonzero with a constant safe diagnostic.
7. Emit the selected path and validated structured projection without copying
   arbitrary artifact content into a shell command.

Update post-release Source B to invoke this selector with current release
metadata and extract only `findings.unresolved` MEDIUM/LOW entries. “No
artifact” and “zero unresolved findings” are distinct outcomes; the former
blocks/explicitly reports Source B, while the latter is a validated clean
result.

### Compression and substitution handoff

All auto-dev deep-verify paths must produce or explicitly hand off the same
schema:

- `standard`: the normal multi-angle deep-verify producer writes the artifact;
- `docs-only-self-review` and `lite-deterministic`: the substituted deterministic
  review writes a schema-compatible artifact with its reduced
  `executionMode`, exact gates, and any unresolved findings;
- `converged-substitution`: when a current equivalent artifact satisfies a
  standard-mode stage, validate and select it by the exact release/SHA before
  recording the substitution; do not relabel an old artifact as current;
- compaction/session handoff: persist and read back the artifact before
  compaction, and place its selected path plus repository/version/SHA in the
  handoff state. Conversation-only prose is not a producer result.

This does not make compressed verification equivalent to standard review. The
`executionMode` and `verificationEvidence` preserve the actual reduced scope.

## Risks, Rollback, and Failure Recovery

### Artifact contract risks

- **False clean through fallback**: mitigated by newest-malformed failure and
  exact release/SHA selection. Never catch selector failure and substitute an
  empty findings list.
- **mtime/cross-midnight ambiguity**: metadata date and all session date
  directories are searched; mtime is ignored and lexical ties are fixed.
- **partial or redirected write**: exclusive same-directory temporary file,
  regular-file/symlink checks, atomic rename, and readback validation.
- **schema evolution**: schemaVersion 1 rejects unknown versions. Roll back the
  producer, selector, and both skill consumers together; do not leave a new
  producer with an old consumer.
- **compaction loss**: write and select before handoff. A conversation summary
  may point to the artifact but cannot replace it.

### Readiness risks

- **Generic-hook false pass**: exact managed identity plus source/trust/enabled
  correlation; unrelated hooks remain insufficient.
- **Overblocking existing doctor use**: the strict result is isolated behind
  `--require-shell-advisor`; general OMX/plugin readiness remains compatible.
- **Trust boundary violation**: no automatic hashes or `/hooks` approval. A
  release may wait for explicit operator trust rather than weakening the gate.
- **Runtime drift**: official 0.144.1 source and native interop tests ground the
  design. If a future Codex removes nested PreToolUse routing, report a runtime
  compatibility defect instead of silently enabling an outer parser.
- **Rollback**: remove the focused API/option and preflight together before
  publication only if verified runtime evidence invalidates the contract;
  retain JavaScript `exit_code` guidance because it is independently safe.

### Triage risks

- **Concurrent label creation**: one post-create exact readback distinguishes a
  benign race; every other create failure propagates.
- **Substring/empty-output false success**: structured exact-name matching and
  explicit command status.
- **Regression of #1677**: existing marker/concurrency/pagination/retry fixtures
  remain blocking and helper changes are rejected without RED evidence.
- **Rollback**: revert only the ensure state machine to a previously verified
  supported lookup. Never restore `gh label view` or mask failure with
  `continue-on-error`/`|| true`.

### Release recovery

- Before tag/publication, revert or supersede the PR with a reviewed fix and
  rerun all affected gates.
- After annotated tag or either registry publication, do not rewrite history,
  delete the tag, or unpublish. Open a new issue/milestone and ship the next
  patch.
- A missing live deep-verify artifact after merge is a release-process failure,
  not zero findings. Preserve the worktree, recover only for diagnosis, and
  fix forward rather than fabricating earlier evidence.
